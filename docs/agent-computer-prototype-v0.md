# Agent 电脑原型 v0（macOS 先行，接口兼容 Windows）

日期：2026-10-21。状态：方案第 3 版已通过独立审查；原型已实现并完成真机验收（结论见 §11）。

## 1. 目标

每个 Agent 拥有一台与宿主同系统的后台虚拟机（Mac 上一台 macOS 客体，Windows 上一台 Windows 客体），作为「Agent 自己的电脑」。Agent 在里面用**自己的业务账号**（微信、邮箱、网站账号等，由用户为 Agent 单独开通）操作；客体内的 macOS 用户只是这台电脑的系统用户，不代表任何人。业务文件的增删改查都在虚拟机内完成，文件经用户确认才进入用户目录。Agent 的鼠标键盘作用于虚拟机，不与用户抢宿主的鼠标、键盘、剪贴板和屏幕。

## 2. 原型范围（本次）

在本仓库新增独立服务 `prototypes/agent-computer`（Bun + TypeScript，独立依赖与锁文件，不属于平台包），不依赖、不修改宿主源码。

1. **虚拟机生命周期**：确保 Agent 电脑存在（从已核验的本地基础镜像克隆，禁用自动清理）、后台无窗口启动、等待就绪、查询状态、关机。
2. **显示与输入**：截图、鼠标移动 / 点击 / 双击 / 右键 / 拖拽 / 滚动 / 按下 / 抬起、按键与组合键、文字输入（含中文）。输入从虚拟机层注入，客体内不需要辅助功能或屏幕录制权限。
3. **文件进出**：收件箱只读共享给客体；出件箱为宿主上**本服务专属的隔离暂存区**，只共享给这台客体。文件写入暂存区不等于交付给用户；只有用户批准的那一版内容才会复制进用户指定的目录（见 §6）。
4. **安全线**：紧急停止（可打断进行中的输入并释放按住的按键）、输入速率上限（按底层事件计）、每步审计。
5. **本地 API**：只监听私有目录里权限 600 的 Unix socket（实施中由 `127.0.0.1` 改来：回环端口可被本机其他进程抢先监听并骗取用户令牌）；Agent 与用户分权（见 §7）。

不在本次：宿主集成与插件 UI 改造、Windows 实现、登录状态 / 聊天记录 / 浏览器状态迁移、多 Agent 调度、通用命令执行接口。

## 3. 实施顺序（技术闸门在前）

1. **契约**：本文 §5–§7 的方法矩阵、文件与授权契约。
2. **闸门实测**（真实 VM，后台无窗口）：VNC 端点发现与握手、截图、鼠标键盘、中文输入、共享目录读写与只读、宿主不受影响。任一不通过先改方案，不写服务。
3. **服务实现**：RFB 客户端 → TartProvider → AgentComputer 安全线 → HTTP API → 用户侧 CLI。每层带单元测试，测试用假 VNC 服务端，在 Linux 上也能跑。
4. **工程接入**：独立目录自带 lockfile 与 test / typecheck 脚本（主干已将平台包移回主项目，原型不放在 `packages/`）；真实 VM 验收单独脚本，普通 CI 不启停虚拟机。
5. **运行时验收**（§9），更新本文结论。

## 4. 分层与 Windows 兼容

```
HTTP API（平台无关，方法与错误码稳定）
  └─ AgentComputer（停止位、输入串行队列、速率上限、审计、坐标校验）
       ├─ VmProvider     生命周期、就绪、共享目录、显示端点    macOS: TartProvider（原型）  Windows: 待定（Hyper-V 等）
       └─ DisplayInput   截图与输入                            macOS: RfbDisplayInput       Windows: 待验证（RDP 或客体内 VNC）
```

- 上层只依赖两个接口，不暴露 RFB 专属类型。`DisplayInput` 带少量能力标志（如 `unicodeText`、`loginScreen`），表达平台差异。
- Windows 显示实现标记为待验证、允许替换；本次不实现 Windows 后端，也不做插件注册框架。
- 启动合同：`CI=1 TART_NO_AUTO_PRUNE=1 tart run --no-graphics --vnc-experimental --no-audio --no-clipboard --dir inbox:<路径>:ro --dir outbox:<路径> <vm>`。`CI=1` 防止 tart 在宿主打开「屏幕共享」，`--no-clipboard` 防止与宿主共用剪贴板。
- 依赖说明：`--vnc-experimental` 走 Virtualization.framework 私有 VNC 接口，固定验证过的 tart 2.37.0 与宿主 macOS 27.0.1；tart 为 FSL 许可，仅限原型使用，接口隔离保证以后替换时上层不动。
- VNC 地址与密码从 tart 输出中解析；含密码的 tart 日志文件权限为 600，密码不进 API 返回、错误信息与审计。实测该 VNC 端口监听所有网卡（见 §11），正式版需收紧。

## 6. 文件出口契约

- 暂存区为宿主私有目录（不在用户文档目录里），只挂载给这台客体。
- `outbox.list` 只列普通文件（拒绝符号链接、设备文件、目录穿越；校验整条真实路径都在暂存区内），返回候选 ID、相对路径、大小、SHA-256。
- `approve(candidateId, sha256, 目标目录)`：以 O_NOFOLLOW 打开源文件，只经文件句柄有界复制到目标目录内的临时文件（权限 600）并边复制边算摘要，与批准时的摘要一致才以硬链接原子落盘；不一致（客体在批准后改了文件）则拒绝。默认不覆盖同名文件，单文件大小上限可配置，中断不留半个文件。
- `reject` 只在服务内标记该版本不再列出，不删除任何宿主路径上的文件（暂存区由客体控制，按路径删除可能被链接替换利用）。
- 目标目录必须在用户配置的允许列表内，且属于当前用户、他人不可写。

## 7. 分权

- **Agent 令牌**：截图、输入、`computer.stop`、收件箱列表。不能恢复、不能查看或批准导出、不能关机。
- **用户令牌**：全部方法。只交给用户侧 CLI（之后是插件界面），存在宿主上仅当前用户可读、未共享给客体的文件里。
- 原型限制：Agent 进程与用户 CLI 跑在同一个宿主用户下，文件权限无法在两者之间强制隔离；宿主集成时改由宿主持有用户令牌。日志不记录任何令牌和 VNC 密码。

## 8. 停止、并发与生命周期

- 所有输入进入单一串行队列；复合操作（长文本、拖拽）拆成底层事件逐个执行，每个事件前检查停止位。
- 紧急停止：置停止位 → 清空队列 → 打断进行中的复合操作 → 通过内部通道抬起所有按住的鼠标键和修饰键 → 之后的新输入全部拒绝。恢复只清停止位，不继续旧队列。
- 速率上限按底层事件计，长文本不能绕过。
- 断连自动重连；重连后先释放按键状态，不清除停止位、不重放旧队列。服务重启时若 VM 仍在运行，接管而不是重启它。
- 服务每次启动或接管 VM 时停止位默认为「已停止」：先释放按键，仍须用户调用 `resume` 才接受 Agent 输入，避免靠重启服务绕过紧急停止。
- 所有权：只操作本服务创建的 VM（名称前缀 + 记录文件），只清理自己的资源。
- 就绪：VNC 握手成功且共享目录已挂载才算就绪；超时报告具体卡点。
- 关机：先请求客体正常关机，超时后再强制停止；确认进程退出后才释放虚拟机槽位。

## 9. 验收方式

自动化（不需要虚拟机）：RFB 握手 / 认证 / 帧缓冲 / 按键映射；停止打断与按键释放；紧急停止后服务重启或连接重建，Agent 输入仍被拒绝；速率上限；分权（Agent 令牌调用 resume / approve 被拒）；只监听权限 600 的 Unix socket、单实例锁；文件出口（未批准不复制、批准后改文件被拒、符号链接 / 穿越 / 同名 / 超大被拒、原子落盘）。

真机（本机 macOS 客体，后台无窗口）：
1. 启动后宿主屏幕上没有新窗口，「屏幕共享」未被打开。
2. 截图得到客体桌面。
3. 在客体「文本编辑」中输入中英文、换行、emoji，截图核对。
4. 期间在宿主连续打字、复制粘贴：宿主的鼠标位置、前台窗口、剪贴板均不受影响。
5. 紧急停止打断一段长文本输入，停止后点击被拒，恢复后可继续。
6. 客体写入暂存区：宿主目标目录在批准前没有该文件；批准后出现且摘要一致。
7. 关机再启动后，客体里的数据仍在（Agent 电脑是持久的）。
8. 测完关机并归还虚拟机槽位。

## 11. 真机实测结论（2026-10-21）

环境：Mac Studio（Apple Silicon，macOS 27.0.1），tart 2.37.0，客体为 `ghcr.io/cirruslabs/macos-tahoe-base` 克隆，后台无窗口运行；临时借用本机一个 macOS 虚拟机槽位，测完已归还。

| 项目 | 结论 |
|---|---|
| 后台运行、宿主无窗口 | ✅ `CI=1` 下 tart 不打开「屏幕共享」，宿主没有新窗口 |
| VNC 握手 | ✅ VNC 密码认证（安全类型 2）；端点与密码从 tart 输出解析 |
| 截图 | ✅ 1024×768；客体分辨率变化（重启后出现 1280×720）由 DesktopSize 处理 |
| 宿主不受影响 | ✅ 全程宿主鼠标位置、前台应用、剪贴板前后一致（未测试宿主同时打字，原型不驱动宿主输入） |
| 英文与符号 | ✅ VZ VNC 按**物理键**解释 keysym、不自动补 Shift（直接发「H」得到「h」、「!」得到「1」）；已改为大写与符号自动补 Shift |
| 修饰键 | ✅ VZ VNC 下 **Alt_L(0xffe9)=Command、Meta_L(0xffe7)=Option**，Super_L 无效；Control 正常。映射按显示通道配置 |
| 中文、emoji | ❌ Unicode keysym 被直接丢弃 → ✅ 改为经 SSH 写客体剪贴板（必须 `LANG=en_US.UTF-8`，否则乱码）再按 Cmd+V |
| 紧急停止 | ✅ 打断 1500 字符的输入（约 90 字符时截断），停止后点击被拒；服务重启后默认停止，Agent 令牌不能恢复 |
| 文件进出 | ✅ 客体挂载于 `/Volumes/My Shared Files/{inbox,outbox}`；收件箱只读生效（写入报 Operation not permitted）；Agent 不能自行批准；批准后被改的文件拒绝导出 |
| 持久化 | ❌ `tart stop` 是「拔电源」式停止（0.3 秒），刚写入的文件丢失 → ✅ 改为先让客体系统正常关机（约 10 秒），超时才强制，并返回 `forced` |
| 显示休眠 | ❌ 客体显示器休眠后 VNC 不回画面，截图超时 → ✅ 准备步骤关闭客体显示器与系统休眠 |

新增发现的风险：

- **VNC 端口监听所有网卡**（`*:端口`），不只是回环地址。同一局域网的人拿到随机密码即可连接。正式版需改用只监听回环的实现，或配合防火墙规则。
- 客体内辅助通道依赖 SSH 与 `admin` 账户免密 sudo（基础镜像默认）。正式版应把这两条固定命令做成客体内的专用小程序，并换掉默认口令。
- 文件出口父目录竞态（Node 无 openat）：详见 README「安全线与已知限制」。
- 首次启动时如果 Agent 在系统尚未就绪时输入，按键会丢失；宿主集成时需要「就绪」判断（如等待桌面出现）。

## 12. 审查后复测（2026-10-22）

独立审查期间改动较多（API 改为 Unix socket、单实例锁、截图合并、取消与超时等），在真机上复测：

| 项目 | 结论 |
|---|---|
| socket 权限 | ✅ 600 |
| 服务重启后默认停止；Agent 不能恢复、不能查看/批准出口 | ✅ |
| 第二个服务实例 | ✅ 被拒（已有服务在运行） |
| 宿主不受影响 | ✅ 鼠标位置、前台应用、剪贴板前后一致 |
| 紧急停止打断长文本、停止后点击被拒 | ✅ |
| 文件出口：批准前目标目录无文件、批准后内容一致、收件箱只读 | ✅ |
| 正常关机（未强制）→ 开机 → 客体数据保留 | ✅ |
| 中文与 emoji 粘贴 | ✅（复测中客体会话恢复后输入正常出现） |

复测新发现（下一版处理）：

- **开机后首个输入前，VNC 只给黑屏**（分辨率仍是开机时的 1280×720），收到一次鼠标移动后才出现真实桌面。截图判断「桌面就绪」不可靠，启动流程需要在用户发起的 `vm.start` 中完成一次显示唤醒，并以客体内登录状态判断就绪。
- **系统未就绪时的输入会丢失**：会话恢复让桌面画面很快出现，但此时 Spotlight 等尚不可用，按键被丢弃。
- **刚开机就关机时，客体内正常关机可能失败并回退为强制停止**（返回 `forced: true`，行为符合设计，但说明就绪前关机有丢数据风险）。
