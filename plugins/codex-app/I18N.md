# Codex App language coverage

Codex App 0.1.9-h08.1 uses one pair of resources: `assets/locales/zh.json` and `en.json`. The package requires Host API `>=1.19.0 <2.0.0` and `metadata.i18n@2`; immutable earlier packages remain unchanged.

The work page, settings, status/relative time, input controls, reasoning effort labels, approval and question controls, loading/empty states, tooltips, accessibility labels, account/login/runtime notices, and plugin-generated toasts follow Host locale. Host locale is read before mounting and its listener is removed on unmount. Existing controls are patched in place; changing language does not initiate polling, drain events, send/approve a turn, sign in, save preferences, or choose a model. New and background surfaces use the latest locale. Unknown locale values fall back to English; legacy Host without a locale API retains the Chinese default.

Controlled messages retained in state carry key/parameter objects. Strings always represent original data. This distinction keeps supplied task names, Skill descriptions, account labels and approval summaries unchanged even when their text happens to equal a generated fallback. Thread activity labels are projected from the retained raw payload, preserving user/agent messages, code/output, paths and IDs. Reasoning labels change without altering protocol enum values or selected model preferences. Existing error notices and validation remain visible in the selected language.

Package-owned store listing, permission purposes and requirement names use the v2 display projection. Remediation and app-intent purposes have no supported visible target; remote Catalog and OAuth authority content keep their original source. Runtime/service diagnostic details and protocol/model/Skill names are original data. These exclusions do not claim translation on unsupported Host surfaces.

Validation uses the plugin's Bun unit/DOM tests, typecheck, strict i18n validate/build/pack and two Host lifecycle contract scenarios. The protocol fixtures are explicit, local and do not launch Codex or call a paid service. They verify English cold start, hidden locale changes, retained draft/focus/selection, zero business requests on locale changes, unmount/reopen, and a retained login failure/navigation label. Packaging checks source and actual archive resources; native App, account authorization, store publication and real model execution remain separate acceptance gates.

Host-facing operation and mount failures use stable `com.reai.codex-app/OPERATION_FAILED` and `com.reai.codex-app/SURFACE_MOUNT_FAILED` AppError codes with localized userMessage and original diagnostic cause. Unchanged user-output and title text is never reassigned during a locale update, preserving browser Range selections; actual in-app-browser red/green evidence is recorded separately in the H06 local fixture artifacts.
