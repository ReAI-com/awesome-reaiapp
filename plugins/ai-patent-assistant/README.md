# AI 专利助手

`com.example.ai-patent-assistant`，源码版本 `0.1.0`。这是开发 Demo，未送审、未签名、未上架。

本插件按 [AI 员工范式](../../docs/ai-employee-pattern-v1.md) 由 `plugins/ai-employee` 的生成器产生，岗位为「AI 专利专员」。它把发明人材料、审查意见和专利文献整理成专利事项台账，用看板跟进九类专利工作。右侧的 Agent 按岗位要求协助挖掘专利点、起草交底书和申请文件、检索解读、对照分析、审查答复和政策简报。所有产出都是草稿，须由人复核。

岗位要求改编自 [handsomestWei/patent-disclosure-skill](https://github.com/handsomestWei/patent-disclosure-skill)（MIT），署名与 MIT 许可全文见 [assets/NOTICE.md](assets/NOTICE.md)，随安装包分发。

## 九项工作

| 工作 | Agent 做什么 | 触发 | 看板 |
| --- | --- | --- | --- |
| 交底书 | 挖专利点、给查新检索式、锁定 D1 与区别特征、按发明 / 实用新型 / 外观设计成文并自检；首篇定稿后可做 1+N 布局 | 默认 | 专利挖掘与交底 |
| 申请文件 | 由已定稿交底写权利要求书、说明书、摘要、附图说明，另附问题清单 | 须点名，且须有交底 | 申请文件 |
| 案卷会稿 | 交底到申请一条龙，分诊问题清单，最多 3 轮 | 须点名 | 案卷会稿 |
| 著录检索 | 按发明人、申请人、分类号等生成公布公告高级查询的字段表和布尔式，整理用户上传的结果 | 默认 | 检索与解读 |
| 专利解读 | 依据上传全文写通俗笔记，把权利要求拆成特征行 | 默认 | 检索与解读 |
| 对照表 | 特征逐格对照对比文件、产品或标准，标强弱与证据缺口 | 须点名 | 对照表 |
| 专利地图 | 基于已解读事项出技术功效矩阵、申请人分布、引证关系 | 须点名 | 专利地图 |
| 审查答复 | 拆解审查意见，给多种策略，选定后出意见陈述书草稿 | 须点名 | 审查答复 |
| 政策简报 | 依据上传的官方原文说明对交底与申请写法的影响 | 须点名 | 政策简报 |

Dashboard「专利工作台」汇总进行中、待人确认、自检有问题、已完成数量和涉及案件数，「自检与待补」看板集中列出有问题和尚未自检的事项。

与原技能的差别：插件不能联网，也不能运行 Python 脚本，不读写 Obsidian。国知局检索、PDF 下载、Word / Excel 导出、线稿与专利地图页面都没有搬进插件。Agent 给出检索式、表格或 Markdown 草稿，由用户在外部执行检索后，把结果作为资料上传。模板最多支持 8 份工作方式，所以专利解读与专利地图合为一份。

## 按 AI 员工范式 v2 的岗位定义

[范式 v2](../../docs/ai-employee-pattern-v2.md) 只完成了设计稿与合同，下表是专利岗位在 v2 中的定位，供第二阶段实现参考。当前运行行为仍是 v1：原始资料 → 标准记录 → 岗位 Agent。

| 项 | 定义 |
| --- | --- |
| 主范式 | A-B-C 创作型，叠加 D |
| A 原始事实 | 发明人技术材料、项目文档、审查意见通知书、专利全文或公开号、检索导出结果、官方政策原文 |
| B 规范数据 | 专利事项台账（本插件的 15 个字段）；将来可拆出专利点与区别特征表 |
| C 交付物 | 交底书、申请文件、意见陈述书、对照表、政策简报、专利地图。由代理师从候选中选定并签字 |
| D 规则检查 | 交底自检、申请材料门禁、权利要求与说明书一致性检查、答复期限检查、查新区别特征三态判断 |
| 回流 | 选定的交底书回流成申请文件事项的输入；解读结果回流为专利地图的数据 |
| 上下游 | 上游为研发与产品岗位提供的技术材料；下游为专利代理机构递交与法务 |

当前 v1 的实现方式：C 以 Agent 报告草稿保存，没有候选、选定与签字回执；D 以「自检结果」「待补事实」字段由人维护，没有规则版本与检查运行。

## 跑通本地闭环

平台包来自仓库根 `vendor/platform/` 中按摘要锁定的 tarball。在本目录执行：

```sh
bun install --frozen-lockfile --ignore-scripts
bun run test
bun run typecheck
bun run validate
bun run build
bun run test:contract
bun run pack
bun run dev
```

打开 `http://127.0.0.1:4189/preview.html`。浏览器预览与插件共用界面和业务代码，资料保存在浏览器本地存储，不代表真实 Host 安装成功。

1. 在设置中填写公司名称和工作要求。
2. 从左侧底部「上传资料」导入 `assets/sample-patent.csv`，或粘贴相同格式的 CSV / JSON。
3. 执行整理，打开专利工作台和各看板，检查事项、状态和来源。
4. 在看板中打开事项，修改状态或自检结果，再查看原件与修订历史。原始字节保持不变。
5. 打开 Agent 询问在办事项。默认「演示分析」使用规则统计，不调用大模型，也不会生成交底书正文。
6. 点击看板导航的 `+`，用自然语言描述新看板，例如「我想要查看侧边栏增加一个外观设计，我的要求是：专利类型为外观设计」，检查提案后确认添加。

示例数据全部虚构。自动整理只支持 CSV / JSON；专利 PDF、Word 和图片只保存原件，不提取内容。

## 能力边界

- **暂无租户、客户与案件隔离**：所有资料与事项在同一个存储里，Agent 读取的原件也不按案件区分。当前版本只适合单一客户的演示，不能用于同时服务多个客户。隔离方案见 AI 员工范式 v2 的后续版本。
- 默认包不申请模型能力。交底书、申请文件等正文生成需要真实模型，需走 `bun run prepare:agent` 准备候选并取得平台批准、用户同意后才可用，详见 AI 员工模板 README 的「真实 Agent 候选」。
- Agent 只能读取和分析，不能直接修改台账；台账由人修改，报告由人确认后保存。
- 产出不构成法律意见，不评价授权概率，不替代专利代理师签字或正式递交。
- 设置页的开发模式仍可切换到模板自带的财务、人事示例岗位，用于对照；专利台账不会被重新解释为其他岗位数据。
- 设置页底部提供版本号与「关于插件」入口，版本取当前 Manifest。
- 也可以把本插件当模板用 `bun run scaffold` 再生成其他岗位。生成器只替换身份与岗位配置，商店文案、README、CHANGELOG 和默认公司要求仍是专利内容，需要按新岗位重写；专利专项测试会自动跳过。

其余合同（HTML 看板、旧数据兼容、生成新岗位插件、语音输入、外部资料适配接口）与 [AI 员工模板](../ai-employee/README.md) 一致。

## 验证边界

本地单元测试、类型检查、CLI 校验、构建、合同测试、打包和浏览器预览分别提供对应证据。真实模型调用、交底书与申请文件的实际撰写质量、联网检索、文档导出、语音、平台审核、签名、真实 Host 安装和商店发布尚未验证。
