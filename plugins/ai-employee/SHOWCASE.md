## 与 main 的模板对比

同一条开发服务同时提供以下入口，可以分别打开对照：

- [main 范式 v2 交互设计稿](design/paradigm-v2.html)：`http://127.0.0.1:4188/design/paradigm-v2.html`。
- [17 岗位界面演示](showcase.html)：`http://127.0.0.1:4188/showcase.html`。
- [原 v1 运行模板](preview.html)：`http://127.0.0.1:4188/preview.html`，用于补充对照已有的数据处理能力。

| 对比点 | main 范式 v2 设计稿 | 本次岗位演示 |
| --- | --- | --- |
| 讨论重点 | 10 个通用岗位的 A-B / A-B-C / A-B-D 工作范式 | 17 个客户岗位与 83 个专属看板 |
| 导航 | 主题看板、分层资料、公司流程 | 员工首页、部门/优先级筛选、岗位任务索引 |
| 创作与检查 | 模拟候选选定签字、内容回流、规则及检查版本 | 岗位场景展示与本地确认状态，未实现 v2 的交付和检查合同 |
| 新增看板 | 演示可信动作与交互流程 | 确认后保存独立记录快照；不会随另一看板记录自动变化 |
| 公司流程与权限 | 只读 IPO 网络、四档权限视角的设计示意 | 无 IPO 网络；岗位切换与开发视图不等于访问授权 |
| 刷新保存 | 页面内存，刷新重置 | 按岗位保存对话、草稿、修订、提案、报告与设置 |
| 文件处理 | 设计演示整理、复核与入库 | 只登记新选文件元信息，未保存或解析上传原件 |

v2 仍是交互设计稿及范式合同，不能据此视为插件业务已实现。原 v1 运行模板实际支持原件字节保存、SHA-256 去重、CSV/JSON 整理与记录修订，其新增 HTML 看板实时绑定标准数据；它与本次岗位演示的快照方式不同。v1、v2 和岗位演示的存储及能力边界分别保留，不互相继承验收结论。

## 岗位演示操作

17 位岗位员工覆盖 18 条需求，内置 83 个范式看板。组织发展的两条需求保留各自优先级和任务来源。CAD 与四个高层数字分身展示概念界面，其中未定义的职责、形象和行动权限保留待确认。

操作入口：

1. 首页按部门、优先级或任务关键词筛选，进入岗位。
2. 左侧切换专属看板，右侧 Agent 使用规则生成 mock 回复，引用在左侧打开。
3. 左侧「+」填写未发送的草稿。发送后先预览提案，确认才加入新看板。新增看板为独立记录快照。
4. 点击工作记录修订字段和原因；历史与只读初始资料保留。预算与库存的确定性派生字段自动重算，其余指标为初始演示快照。
5. 对话、草稿、修订、提案、报告和岗位设置保存在浏览器的独立演示存储中。文件选择只保存元信息，不保存或解析文件原件。

品牌与菜名语境参考[巴奴官网](https://www.banu.cn/zh-CN#eleproduct)，央厨背景参考[新华网](https://www.xinhuanet.com/finance/20250326/dde7f0fd054448a5a8468e611d7c7007/c.html)。人员、经营指标、库存、金额、合同、案件、路线与日期安排均为虚构样例。

演示入口 `showcase.html` / `src/showcase.ts`，岗位配置在 `src/showcase/roles-*.ts`。原 `preview.html`、Host 应用入口、模型与语音流程均独立。本演示没有正式审批、系统同步、消息发送、下单、模型调用、视频识别或 CAD 制图能力。

验证：`bun test`、`bun run typecheck`、`bun run build`、`bun run test:contract`、`bun run build:showcase`。合同检查需要先构建原插件。
