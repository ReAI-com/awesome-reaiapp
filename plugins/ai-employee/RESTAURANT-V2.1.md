# 餐饮 AI 员工 v2.1：岗位整合原型

日期：2026-10-15。本页先对比功能缺口，再记录餐饮岗位的整合方式与演示边界。它是基于 [AI 员工范式 v2](../../docs/ai-employee-pattern-v2.md) 的场景原型说明，不替换原合同，不改变插件安装包版本，不代表正式产品或平台能力已接入。

视觉沿用原巴奴岗位版：暖白背景、墨绿主操作、鼠尾草侧栏、白色细边卡片及低饱和概览；首页保留欢迎区、工作概览、示例待办和岗位卡片的设计语言。岗位内继续使用 v2 的资料、交付、检查与 Agent 结构，明暗模式和手机布局保持可用。

## 功能缺口与整合选择

| 能力 | main v2 范式 | 现有 17 岗位版 | 餐饮 v2.1 的选择 |
| --- | --- | --- | --- |
| 工作范围 | 10 个通用岗位的范式示意 | 17 位员工、18 条需求、83 个看板 | 保留岗位和全部工作内容，组织为 58 个主主题；原看板成为主题内业务分区 |
| 导航与布局 | 岗位主题导航、中央工作台、右侧非模态 Agent | 员工首页及专属看板 | 沿用 v2 的布局、主题和四档视角，加入餐饮对象与任务覆盖 |
| 资料整理 | 原件→整理→整批复核→发布记录 | 内置文字资料；用户文件仅登记元信息 | 内置虚构整理样例可复核发布；用户实际上传不套样例结果，未提供通用整理器 |
| 原件边界 | 设计稿演示原件与指纹，不等于正式存储 | 上传文件原件没有保存 | 新页只在有界浏览器内存保留可读取的原件；刷新重置，不上传到服务器 |
| 记录与来源 | 来源链、记录版本、更正冲突 | 字符串行、来源引用与修订历史 | 复用 v2 的来源与期望版本交互；餐饮分区和新增看板读取同一岗位记录集合 |
| 交付 | 多候选、选定、签字、版本回执 | 报告和普通确认草案 | 为排班、设计、预算、线路、资料包提供候选；选定与演示签字分开 |
| 输入更新 | 保留旧签字，标明基于旧输入 | 无候选输入版本关系 | 保留候选、输入版本引用与回执，输入变动后提示重新生成 |
| 交付回流 | 签字内容快照另存新资料，再整理入库 | 没有交付回流对象链 | 保留候选→derived 原件快照→待确认整理→新记录的链路，不直接改表充作回流 |
| 检查 | 规则定义与运行分开；冻结输入版本 | 检查表和样例状态 | 按规则与证据运行本地样例，区分通过、业务未通过、运行失败、证据不足 |
| 结论过期 | 规则或输入更新后需重新检查 | 不具备正式过期关系 | 保留历史运行；规则、记录版本或整表成员变化后提示过期 |
| 看板调整 | 声明式绑定、可信动作、只读提案、确认幂等 | 新看板复制独立行快照 | 新增看板绑定当前岗位记录；预览不能操作；字段、动作或配置过期均可拒绝 |
| Agent 确认 | 消息 parts、对象引用、单向 Interaction | 文本、链接与一个通用提案 | 复用 v2 确认卡；“已回答”与“业务提交结果”分开；步骤明确标演示 |
| 公司流程 | 只读 IPO 投影，按视角缩小范围 | 无公司流程 | 展示餐饮拟议资料流；节点、箭头和视角都不构成真实跨岗授权 |
| Agent 配置 | Manifest 默认值与 Host 用户覆盖 | 页面内岗位设置 | 生效配置只读；Host 修改入口只演示说明，不另建引擎或提示词编辑器 |
| 刷新与旧数据 | 原 v2 页面内存，刷新重置 | 旧岗位版按岗位保存 localStorage | 新页沿用内存原型边界，不读写旧版 localStorage，不继承旧版保存能力 |
| 外部动作 | 云能力、格式导出等有待确认 | 本地草案，无外部调用 | 不发送、不派车、不下单、不发薪、不签章；正式接入单独实现与验收 |

main v2 提供状态合同和信息架构；17 岗位版提供餐饮工作内容。合并的重点是把工作内容放进可追溯的资料、记录、交付和检查关系，而不是把原有静态表格换一层外观。

## 独立入口与保留范围

新页面：[`design/restaurant-v2.1.html`](design/restaurant-v2.1.html)，本地预览路径 `/design/restaurant-v2.1.html`。

同一开发服务保留三个对照入口：

- [`design/paradigm-v2.html`](design/paradigm-v2.html)：main 的通用 v2 交互设计稿。
- [`showcase.html`](showcase.html)：原 17 岗位、83 看板的岗位演示。
- [`preview.html`](preview.html)：原 v1 运行模板。

本次只新增页面、生成代码、测试、构建配置和本文。新 HTML 由 `plugins/ai-employee/scripts/build-restaurant-v21.ts` 读取原 v2 后生成副本，复用原生交互运行时。生成器和餐饮扩展位于 `src/restaurant-v21/`；其中 `catalog.ts` 定义岗位、主题与覆盖关系，`generator.ts` 注入配置，`runtime.js` 和 `runtime-extension.ts` 提供新页的受限交互与样式。不能手改生成 HTML 后把它当成事实源。原页面、Manifest、包脚本、锁文件及旧浏览器存储均保留。

这是**内存交互原型**：同一次打开期间岗位草稿、对话、候选和待确认事项隔离，刷新页面后全部重置。切换演示岗位不等于在产品的同一插件实例中切岗；正式产品仍按一岗一实例设计。页面里的公司配置只影响本页演示，不修改真实公司、Host 或旧版本。

组织发展的两条需求属于同一位员工，两个需求编号和优先级均保留。17 位员工包括 12 个常规岗位、1 个 CAD 范围讨论岗位和 4 个数字分身概念岗位；后五个包含在总数内。

### 各岗位必须保留的业务含义

- **训练平台管理**：区分待排需求、讲师资格/可用时间、场地设备与硬约束；午晚市偏好不等于禁止条件。保存班表只生成演示交付，不意味着通知已送达或培训已执行。
- **训练稽查**：保留收卷、评分项、证据时间段、异议、改判理由和补考。遮挡、无声、没有秤屏等显示无法判定或证据不足；初评不充当最终成绩。
- **营运评估**：巡店排班、OCR 提取核对、称重、出品外观、训练会和迎宾六项分别保留。视频不推算真实重量，外观不证明温度、味道或食品安全。整改责任人、期限和复查证据不全时不宣称闭环。
- **VI 设计**：简报、多概念、打回改稿、多尺寸延展、批量场景、资产和质量核验均保留。原需求的生成耗时、节省比例和通过率是目标，不是本原型测得成绩；HTML 候选是概念示意，不是可编辑设计源文件。
- **空间设计**：基底图版本、尺寸和单位、设备参数及制图范围缺项必须可见。候选仅用于布局/资料准备讨论，不能称作施工图、DWG/DXF 或专业工程校验；不得猜单位、消防要求或工程可行性。
- **造价**：数量、单位、单价、来源和计价范围分别保留；缺工程量或价格不能按零处理。样例预算不是图纸自动提量，也未自动涵盖税费、设计费、预备费等完整项目成本。
- **供应链计划**：库存/订单、到货、异常、新品测试四条工作链都保留。采购与调拨分开，脏数据造成的假预警与真实短缺分开。现存可用天数为“现存 ÷ 日均”，含在途覆盖为“（现存＋在途）÷ 日均”，不能混为一个数；日均缺失不能计算。7–10 天短保规则的适用品类及参数仍待确认。
- **调度**：线路、车辆、容量、时窗、未分配和执行异常保留。图上连线为示意，不证明地图路线、里程、工时、温区或装载已经可执行；选定方案不等于派车。
- **组织发展**：保留说明书版本、三套审批、重复经理节点跳过、驳回原节点续办、敏感导出/水印、历史留存、年审不变不升版与系统联动需求。这些正式审批和控制未接入。组织自检与后台人工成本诊断分开；人数差值不能推导浪费、裁员或调薪，指标分子分母、时点、FTE 和比较规则需确认。
- **绩效政策**：周期催办、说明书模块/KPI 一致性、战略映射、实际值缺项/异常、群体系数、结果同步分开。采购阶梯、组织严格大于阈值阶梯、区域招聘“分数 ÷ 100”、其他群体等级系数不能合成一个公式。分数、政策调整、系数和奖金配置分开；奖金的群体、职级、现金/股权及时点另行核定，不能用“分数 × 工资”代替。7 日 24:00、最后 24 小时每小时提醒/电话是需求节奏，不代表已经催办。
- **人力共享**：保留外包每日入离转、离职回访、每月/季度满意度及名册分母、周一供应新员工分类、管培生月考勤、每周发薪前人员/银行卡及重复外出排班核验、每月 1 日职级比例七项。银行卡只展示确认状态，不使用真实账号；月 3 日等节奏不当作已完成日期。
- **区域招聘**：17 项任务继续覆盖：周材料、月绩效、背调费用、账号席位及组织映射、团队/门店费用、缺编与新店、供应商/渠道效率、渠道到期、阶段/日报、前厅 AI 初面、软件招呼、无编制锁定、内推二维码、候选门店评价、BOSS/58 虚拟面试与日历、全渠道简历去重导入、按岗位简历和面试。阶段/日报字段待定，前厅初面不含后厨；联系、邀约、录用、付款和有效二维码发布均未发生。
- **法律事务**：保留 16 类去重事项：合同审查、营销事实依据、合同系统支持、危机支持、IPO/投资/并购/海外、法律咨询、档案、研究、涉诉文书、知识产权、品牌保护、商标授权/电子章、印章台账、电子借阅、证照/法人资料、线上线下合同对比。检查不构成正式法律意见；危机与专业判断仍交人工。证据有效期、授权条件和原文版本必须可追溯。
- **董事长与执行总裁数字分身**：已知需求是人设与形象；持续职责、真实素材、表达权限和行动清单未提供。资料包、经营议题或协调简报仅是界面假设，不代表本人观点、经营决议、承诺或对外发言。
- **两位副总裁数字分身**：分别保存范围问题和素材。分管业务、与另一位的分工、上下游与产出均待客户明确，不默认其中一位负责营运或财务。

## 可操作的本地交互与验收目标

以下是新页的交互约束和验收目标，不是未执行检查的通过报告。状态只在当前页面内存中演示，不形成真实业务记录。

### 资料与记录

1. 内置样例明确标为虚构资料及预置整理结果。打开“去确认”，存在未处理问题时整批不发布；显式处理问题后确认入库，重复确认不能重复加入。
2. 记录能回看对应原件、整理规则引用及来源类型。更正需核对期望版本；版本冲突后刷新再提交，原件不随更正改变。
3. 原主题分区和新增看板读取同一岗位当前记录集合；新增看板保存定义与绑定，不复制静态行数据。记录修改后展示按绑定更新。
4. 用户实际选择的文件在单文件 8 MiB 读取上限内保留当前页原件。超过读取上限只登记元信息并明确未读取原件；不把元信息指纹当内容指纹，不宣称持久保存。文本粘贴同样没有通用餐饮整理器，不能自动套用内置样例行。
5. PDF、图片、音视频和办公文件未提供解析器。能读取文件不代表能识别或自动整理。界面应说明未上传服务器、刷新丢失和不支持自动整理。

### 交付候选

- 候选绑定具体版本及生成时的输入记录版本集合，重新生成保留旧版本。用户先选定，再作演示签字，不能用一个“确认”把两个步骤混合。
- 回执包含演示签字者、时间、候选版本、输入版本和幂等键。同键同请求重复提交返回原回执；同键不同请求拒绝。
- 输入更新后保留旧签字，并标明基于旧数据，不把旧回执当作本次新内容的签字。
- 回流读取已签字候选的规范内容快照，另存新原件，再进入样例整理/复核。正式 Word、PPT、Excel、设计源文件或 CAD 导出不在此链路中冒充已实现。

### 检查与人工处理

- 检查定义与运行记录分开；开始时冻结规则版本与输入版本引用。若读取岗位整表，冻结成员集合与版本，后来新增/删除记录也使旧结论过期。
- 四种结果分别呈现：通过、业务未通过、检查运行失败、证据不足。缺证据不判业务违规，运行失败不伪装成检查已完成。
- 规则或输入更新后保留旧结果，标“需要重新检查”。过期结果只供查看/解释，不能继续提交人工升级。
- 人工升级生成本地确认和演示处理结果，不发送消息、通知、电话或任务。检查结果不能替代法律、食品安全、工程、用工或薪酬专业决定。
- 新页在记录修订历史中保留字段值，并在检查启动时复制本岗字段快照；证据详情可对照运行当时的值。它仍是本页内存演示，不是正式历史仓库，也未读取外部对象的历史值。

### 看板提案、Agent 与权限视角

- 提案只引用已有组件、字段和可信动作，预览只读。确认前再次校验，未知字段、未知动作和岗位配置过期分别拒绝；重复确认不重复加导航。
- 消息使用正文、对象引用和确认卡等 parts。工具步骤标“演示”，不伪造真实模型思考或服务事件；点引用回到本岗对应资料/记录/交付/检查。
- Interaction 从待回答走向已回答、取消或过期；已回答不回退。答案和提交结果分两步，后者仍可冲突或失败。
- 同次打开中的草稿、消息、待确认对象按岗位隔离。切岗前的异步结果不能写入另一个岗位。关闭重开 Agent 保留当前会话，但刷新页面重置。
- 员工看自己与直接上下游，负责人增加本部门，管理员增加全公司，开发者增加技术字段与工作流说明。它们是展示视角，不是安全权限实现；别岗资料清单只读，节点跳转不扩大授权。
- Host Agent 配置只展示默认/用户覆盖等来源和模拟入口；不在本页编辑真实提示词、引擎或平台配置。开发模式密码只防误改，不替代权限。
