# 语音输入法更新日志

## 2.15.0

### 语音 Agent 只有一个「Agent」，文件夹读权限记住一次就够

候选状态：送审版本，未上架。本条对比平台已批准的上一版本 `2.14.8`。

- **只有一个 Agent**：不再出现 Pi / DSH / Codex 的名字，也没有「Agent 配置」页、引擎选择与内核标签；由 Host 决定用哪个 Agent（当前只用 Pi）。总结、翻译与语音任务统一走 Host 默认 Agent；安装要求只剩「ReAI Agent Runtime」一项。
- **文件夹读权限只问一次**：Agent 第一次读到工作范围之外的文件时，Host 弹一次确认；勾上「以后读取这个文件夹不再询问」后，这个文件夹（含子目录）的只读访问不再弹窗。写入与命令仍每次确认。
- **拨杆决定能不能改**：按键触发时 Host 带来拨杆档位（Host API 1.29 `workMode`），新建的 Agent 会话按它定档——chat 只读、plan 只能改计划文件、yolo 才可写可执行；续接已有对话（对话页追问、结果弹窗还在时再按语音键）沿用那条对话已有会话的档位、不跟拨杆，没有拨杆的设备或软件入口新开的任务按 chat（只读）。已在进行的对话不随拨杆切换改档。
- **结果弹窗还在就接着聊**：Agent 结果弹窗还显示着时再按语音键，是续接那条对话而不是新任务；弹窗关掉或被顶掉之后才新开（Host API 1.29 `visibleAnswer`，旧 Host 保持原行为）。
- 清理：删掉 Agent 实验设置、对话级 Agent 切换与相关文案；安装要求与权限说明去掉引擎名。
- 兼容：Manifest 的受控能力集、权限项与 Host API 范围（`>=1.25.0 <2.0.0`）与 `2.14.8` 相同，只有 `agent.session` 两项权限说明去掉了引擎名。拨杆档位与结果弹窗续聊需要 Host API 1.29 的 Driver（1.0.7 beta 之后的版本）；旧 Driver 上这两项保持 `2.14.8` 的行为。

本地测试、类型检查与构建结果见本次合并请求。SOURCE 审查、平台批准、签名、真实 Host 安装和商店上架各自需要证据，本条目未包含这些证据。

## 2.14.8

### 上下文时间线更好用，短句润色不再答非所问

发布状态：已上架。2026-10-25 平台审核通过并发布为公开版本，替代此前的公开版本 `2.14.8-rc.2`。本条对比 `2.14.6`；`2.14.8-rc.3`、`2.14.8-rc.4` 未单独上架，它们的改动随本版本一起发布，详见下方各条。

- 改进：上下文时间线里连续的「暂无有效文字」段合成一行，显示时段与段数，展开后各段仍可点进详情。
- 新增：时间线底部「加载更早的记录」，按页往前翻；之后的刷新、轮询和删段保持已翻到的页数。
- 新增：当日总结的要点末尾带来源时刻，展开后点时刻进入那一段的原文。总结提示词升到 `voice.digest.day-summary@2`；旧总结重新生成后才有链接。
- 修复：列表分页截断时，过去那一天只翻到一截的段不再拿去重合，避免完整的当日总结被覆盖成残缺版本。
- 修复：只说一个短词（例如「语音输入」）时，润色不再把它误当成对话，写进「请提供需要整理的语音转写文本」这类反问。4 个字以内的短句直接按原话写入；更长的转写放进标记里交给模型，润色提示词升到 `voice.polish.spoken-text@3`，明确不许反问或索要内容；模型输出里漏出标记时保留原话。
- 包含：`2.14.8-rc.4` 的连续多段录音、`2.14.8-rc.3` 的按设备选麦、`2.14.7` 的 PDF 解析修复。
- 兼容：Manifest 权限与受控能力集与 `2.14.8-rc.4` 相同，Host API 要求不变。

送审包采用可复现 Deflate 压缩（Project 单文件上限 5MB），SHA-256 `146077dcce9002a94b27499bfb8f815c945200ee2772bde0129f8aff555ad592`，2,960,125 字节。送审前的源码审查由独立 AI 审查代理完成，平台人工审核通过后发布；发布预检确认安全配置未变，已有用户无需重新授权。真实 Host 安装和当日总结是否稳定带出来源时刻尚待实测。

## 2.14.8-rc.4

### 连续说几段，不用等上一段写完

候选状态：未发布。本条对比本仓库上一源码条目 `2.14.8-rc.3`（未上架）；平台已批准的上一版本为 `2.14.6`。

- 新增：配合 Driver 1.0.6 的胶囊叠放，用键盘或录音卡说完一段后可以马上说下一段。上一段在后台识别、润色、写入，不再挡住新的录音。多段文字按说完的先后写入。
- 改进：每段的写入位置、润色档位、命令类型在按下那一刻就定下，后面一段不会改掉前面一段。
- 改进：Agent 提问来自叠放的录音时，任务卡从那一枚胶囊交接到角落。有新一段正在录音时，结果改到后台完成后再弹出，不打断录音。
- 改进：Driver 的识别切片已经补上按键前的开头时，不再对同一段录音做第二次识别。
- 兼容：旧版 Driver 不支持这些能力时，照旧一段说完再说下一段，行为不变。权限声明和 Host API 要求不变。

本地测试、类型检查和校验结果以送审材料为准。连续多段与 Driver 1.0.6 的联调、真实键盘与录音卡的真机验证、SOURCE 审查、平台批准、签名和商店上架各自需要证据，本条目未包含这些证据。

## 2.14.8-rc.3

### 按哪个设备说话，就用哪个设备的麦克风

候选状态：未发布。本条对比本仓库上一源码条目 `2.14.7`；平台已批准的上一版本为 `2.14.6`，中间的 `2.14.8-rc.2` 未上架。

- 改进：用录音卡或键盘的按键开始语音输入、翻译、转文本或 Agent 提问时，会告诉 Driver 是哪个设备发起的，Driver 优先用该设备的麦克风。键盘和录音卡同时在线时，按录音卡就用录音卡的麦。
- 改进：你选的音源档位仍然优先，例如「只用电脑麦」时按录音卡也用电脑麦。在界面上手动开始语音的行为不变。
- 修复：Agent 回答里的来源链接改由 Driver 打开。总结失败时给出更明确的原因。免费云端识别模型恢复可选，失败时保留清楚的修复提示。（来自未上架的 `2.14.8-rc.2`）
- 兼容：旧版 Driver 不认识设备来源信息时忽略它，照旧按音源档位选麦。权限声明和 Host API 要求不变。

## 2.14.5-dev.3

### 文档附件与语音记录体验改进

候选状态：未发布。以下介绍对比本仓库上一源码版本 `2.14.4-rc.3`，不把该源码版本当作上一商店发布版本。

可以在支持的模型中读取 PDF、XLSX 和 XLS 附件正文。语音记录更便于查看和复制，附件提交和失败提示更加明确。

- 新增：根据模型能力和读取开关接收文档附件，提取 PDF 和表格正文供 Agent 使用。
- 改进：附件与消息一起提交。连续语音片段按原始时间合并显示，并保留可展开的原始片段。
- 改进：语音记录的复制按钮在鼠标悬停或键盘聚焦时出现，触屏设备保持可见。云端模型设置只显示模型名称。
- 修复：限制 PDF 解码分配，检查表格格式、文件链和链接范围。无效、加密或超限文档显示相应失败原因，不静默返回部分正文。
- 修复：PDF 接近预算上限时使用有界的小块扩容，避免频繁复制缓冲区，并保留后续数据流的容量。累计解码预算、分配前拒绝和 Worker 时限保持不变。
- 修复：保留云端模型选择失败的实际错误提示，并区分普通用户提示与开发诊断。
- 使用提示：要求 Host API `>=1.23.0 <2.0.0`。权限声明保持原有范围。文档提取仍有文件、条目、解压大小和执行时限，不支持任意大小的文件。
