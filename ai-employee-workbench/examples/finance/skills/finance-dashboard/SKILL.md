# 财务看板生成

你负责基于 B 生成独立、自包含的中文财务 WebApp。看板是业务界面，不直接等同于 C 交付物；C 仍需独立生成、选定与签字。遵循调用方规定的 JSON 输出格式和安全边界，只使用当前工作区已发布的 B 数据。

## 取数与展示

1. 先识别真实 Schema、业务字段和数据集 ID；必要时调用 `read_schema` 与 `query_records` 查看样本。不能凭空猜测字段。
2. 生成页面使用注入的 `window.employee`：`schema()` 读取结构，`records(datasetId, offset, limit)` 分页读取记录，业务字段位于 `record.data`。持续分页直到覆盖返回的 `total`，不能用第一页当完整数据。
3. 页面每次打开和用户点击刷新时读取当前 B，显示加载中、读取失败和空数据状态。指标从本次实际记录计算；不得嵌入本演示的预期答案或复制查询样本作为正式数据源。
4. 使用原生 HTML/CSS/JavaScript，可用 SVG/Canvas。无外部 CDN、网络依赖或第三方脚本。资料字符串通过 `textContent` 渲染。
5. 显示截止日、期间、币种、金额单位、数据刷新时间、来源表及可展开明细。提供日期筛选、收支分类筛选和刷新按钮，保持中文标签清晰、移动端可读。

## 指标计算

- 以整数分完成加减汇总，最后除以 100 展示人民币元；展示千分位和两位小数。不得把元再除以 100，也不得重复乘以 100。
- 现金收款 = `direction === 'receipt'` 的金额之和；现金付款 = `direction === 'payment'` 的金额之和；净现金流 = 收款 − 付款。付款金额本身是正数。
- 发票应收总额独立统计。只有流水中明确的 `invoice_id` 才能与发票关联，且只用收款核销；付款、空关联和币种不一致不得参与核销。
- 同一发票允许多笔回款。每票未收 = 发票金额 − 截止日已收款。负值表示超额收款，应独立展示异常，不隐藏为普通未收，也不跨客户冲抵。
- 演示截止日默认为 `2026-10-28`，并让用户可见、可修改。到期日严格早于截止日且未收大于 0，才计入逾期未收；截止日当天到期不算逾期。发票和收款均排除截止日之后的记录。
- 应收快照必须使用截至截止日的全部相关发票和收款，不能受现金收支图表的起始日期截断。不同指标的时间口径应在页面标明。
- 不同币种分别统计。缺少必需数据时显示“暂无依据”，不能把数据缺失表示成 0。出现重复单据 ID 时提示数据问题，不静默双算。

## 页面内容

优先实现现金收款、现金付款、净现金流、应收未收、逾期未收五张指标卡；收支分类图；流水表；逐票核对表。表格展示原始业务单据编号，支持查看记录版本与来源。

不展示未经数据支持的利润、毛利率、税额、现金余额或完整财务报表。没有期初余额依据时不推算期末余额。只有存在预算或可比期间数据，才能增加差异分析，并明确比较基准。

默认看板用于阅读。若用户明确要求修改 B，只通过运行环境的 `employee.create` / `employee.revise` 接口完成，并展示错误、版本冲突和实际结果；不要声称写入外部账务系统。

业务方法参考见本目录上两级的 `SOURCES.md`。本技能为本地应用原创编写。

## 生成前的计算自检

- REST 返回的是系统记录包装 `{id, data, version, ...}`。所有业务字段必须从 `record.data` 读取。先统一解包或显式使用 `.data`，不可把包装对象当发票对象。
- 只编写一份逐票核对计算，产出发票额、已收、未收、逾期等派生对象；汇总卡片与明细表共用这份结果，不能分别实现容易分叉的公式。
- 汇总前验证金额是有限的安全整数。任何非法金额应显示数据错误并停止对应汇总，不能显示 NaN，也不能用 `|| 0` 隐藏缺失。
- 币种选择默认为当前实际单一币种；多币种同时展示时分别分组，禁止“全部”混加。所有卡片、图表和发票明细遵循同一币种选择。
- 默认现金起始日为 2026-10-01，截止日为 2026-10-28；应收快照仍包含截止日以前的所有发票与回款。
