## 已完成的真实模型演示

“财务 Demo · GLM 真模型”工作区保留全过程：

- 从两份空 Schema 的规范开始，模型路由银行流水和发票资料，自动生成两张 B 表 Schema，发布 8 笔流水和 3 张发票。
- `node examples/finance/verify.mjs <工作区ID>` 校验日期、整数分、来源行号、原件版本和数据值。截止 2026-10-28：收款 48,000 元、付款 36,280 元、净现金流 11,720 元、发票总额 60,000 元、未收 12,000 元、逾期未收 2,000 元。
- 岗位问答使用 `read_schema`、`query_records` 和 `calculate`，给出 11 个记录版本引用。明确指出仅凭现金流水不能推导净利润。
- D 规则检查执行成功，业务结果为“不通过”：存在 2,000 元逾期应收。业务失败不等于模型任务失败。
- C 生成财务简报候选，保持未签字状态，不代替用户选择或签署。
- 看板通过 REST 获取实际 B 数据，读取分页；浏览器切换截止日后指标变化，恢复日期并刷新后恢复正确结果。

## 过程中发现并修正的问题

这不是一次生成即全部正确的演示：

- 一次清洗的来源行号从 1 开始，补充 CSV 表头行规则后重跑修正。
- 原问答出现加减法错误；接入确定性整数运算工具后重新验证。
- 生成看板先后出现记录包装读取错误、截止日和超额收款处理错误。模型迭代修正后仍有卡片字段名错误，最后由开发者修复卡片构造函数，并补充空数据、截止日、超额收款和正常数据校验。
- 服务曾返回限流错误；保留失败记录与旧 B，等待后重试成功。新自动清洗队列串行执行，失败不无限自动重试。

因此，真实模型连通、数据发布和 UI 闭环已得到证据；任意文件理解准确率与任意看板生成质量仍需按具体输入验收。

## 标准财务库与人工确认

标准库覆盖 14 类基础资料。固定标准 Schema 的映射归集与前述空 Schema 自动推导是两条不同的验收路径。一客户一工作区。凭证、科目与期初可人工确认具体记录版本；修改后旧确认不能用于新版本。

账簿计算验证借贷平衡、明确期初、科目引用、整数金额与币种。财务报表要求选定会计制度、完整依据、经人工核对的项目映射/结转/现金流分类；结果标为管理报表草稿。它不等同法定申报、自动纳税或专业会计最终审核。

## 验收边界

- 用户真实文件和真实问题尚未提供，盲盒正确率、实际问答准确率及用户自定义看板验收尚待进行。
- 无扫描 PDF OCR。混合客户、混合业务或缺失关键事实的文件应进入复核；当前每个文件一次清洗路由到一个规范，不宣称任意多表文件自动拆成多类账目。
- 本机单用户、无多人权限系统，未做大规模压力、远程部署或法定报表合规认证。

## 标准库实际验收结果

使用 GLM 将 6 份独立合成 CSV 经浏览器上传，最终 5 份发布到 5 类标准 B 表，共 16 条记录；多客户/多业务混合文件拒绝路由，0 条发布。

- 银行异名表头、销项发票与凭证分录最终自动清洗发布；科目、期初两份资料经开发者在浏览器复核后发布，不计为全自动。
- 银行与发票首次遇到限流；重试时模型为缺少可选字段列出过多 issues，银行暂存结果还包含无原件依据的余额 0。该批未发布。调整提示词明确“无依据可选值省略、正常转换不是异常”，保留旧失败/取消记录后重跑，最终发布数据没有虚构余额。
- 后续补入 CSV/TSV 真实物理行号及 XLSX 工作表/行号覆盖检查。漏行或虚构来源进入待复核；非表格财务原件不能自动证明逐行完整性，要求人工复核。
- 科目、期初与完整凭证共 12 个实际记录版本，在合成测试工作区通过页面确认。总账银行期末 1,100 元，本期借贷各 140 元，试算平衡。
- 经页面保存本合成账目的报表映射，三表管理草稿均生成：资产/权益各 1,100 元，收入 120 元、费用 20 元、利润 100 元，现金净增加 100 元。映射与确认只应用于合成工作区。
- `node examples/finance/standard/verify.mjs <工作区ID>` 当前 88 项只读断言通过，包含来源文件指纹、行数、字段、金额、Schema、确认版本、账簿及三表；原始双表 Demo 验收脚本也再次通过。

## 浏览器交互与持久化

- 岗位专家右侧栏可打开/收起；Markdown 标题、列表、表格可读，记录引用可打开原件文件名、字段和指定版本核对窗。
- 同一个已发布看板通过页面源码编辑保存 v2，内嵌 iframe 与已打开的独立窗口均自动加载新标题，无需重启服务；通过历史恢复生成 v3，保留 v1/v2。
- 模型结果与业务数据不混入用户验收工作区。“财务代账 · 用户验收账套”已启用14类规范、三个 GLM Agent 和自动归集，仍为0份文件/0条记录，会计制度待用户按客户确认。
- 76 项自动测试和生产构建通过。公开文件凭据扫描无命中，本机 SQLite 权限为0600。

- 看板 Agent 真实更新成功生成 v4：只新增页眉说明，v3→v4 的 script 内容逐字相同；浏览器六项指标正确，截止日切至 10-06 后变为 42000 / 36200 / 5800 / 60000 / 18000 / 0，恢复 10-28 后恢复基准值。独立预览通过版本轮询自动加载。
- 标准账套岗位问答实测：净现金流 914.50 元，凭证借贷各 140 元，工具实际执行整数运算并引用记录版本。初次回答错误地把清洗初始状态当当前人工确认状态，因此补充了查询工具的独立确认元数据；原件字段不被改写。

- 确认状态修复后真实复测通过：Agent 查询并正确说明科目、期初、凭证各4条已人工确认，保留此前错误与更正记录。新增2项确认查询测试覆盖版本变化、分页和工作区隔离。
- 刷新工作台后保留各岗位当前页面；浏览器验证已发布看板仍显示v4及相同指标。
