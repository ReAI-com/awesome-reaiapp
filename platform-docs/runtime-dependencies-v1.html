01 · Classification

八种依赖，一项只能选一个主分类

build_time

只在编译、测试、签名和发布时使用。例：Bun、Rust、Cargo。

bundled

编译进二进制或随安装包交付。用户不需要准备。

os_capability

操作系统自带能力或用户授权。例：WebKit、TCC、Shell。

installer_managed

由商店或 ReAI 安装器安装和修复。例：WebView2。

optional_external_tool

用户主动选择的外部软件，只影响对应功能。

downloaded_content

Host 下载、校验的非执行内容。例：STT 模型。

remote_service

外部网络服务。必须定义离线和暂时不可用状态。

hardware

物理设备与系统驱动栈。必须支持未连接和热插拔。

不能把可执行代码伪装成内容下载

下载后会执行的代码不属于 downloaded_content，必须回到发行策略中按可执行插件代码审核和交付。

02 · Runtime Architecture

组件可组合，硬件按服务接入

v1.1 不再假设一个 App 只有一种运行形态，也不把 AI Board 01 写成平台级前提。

web-surface

协议 web-surface@1。隔离 UI renderer；不能访问 Host DOM、原生命令或直通网络，固定非 headless。

wasm-component

协议 wasm-component@1。Host 沙箱内的业务或后台逻辑；可 headless，限制资源和导入能力。

remote-service

协议 remote-service@1。通过 Network Broker 连接云服务；远端响应只能当数据。

native-companion

协议 native-companion@1。随包审核和签名；默认仅 direct，生命周期由 Supervisor 管理。

runtime.components[]

  • 每项至少声明 id / kind / protocol / required / entry|serviceRef / headless / activation。
  • protocol 必须与 kind 匹配并版本化；Host 不认识时 fail closed。
  • Package 代码使用 entry，remote-service 使用 serviceRef，两者不得并存；web-surface entry 固定为 ESM。
  • platforms 只能是顶层 targets 子集；dependsOn 省略等价于空数组。
  • 本地代码通过 lifecycle.activate / deactivate 映射审核 Hook；远端组件没有本地 Hook，停用只撤销 Broker 会话。
  • Surface、Command、后台任务、文件处理器必须用 componentId 引用执行组件。

状态正交：activation=active 只表示用户允许 Host 运行 App；on-demand Component 仍可以是 stopped。required Component 失败聚合为 health=unhealthy，optional Component 失败聚合为 health=degraded，都只阻断引用它的 Contribution。只有用户停用、更新切换、卸载或明确安全策略才进入 stopping → disabled。

Headless

  • App 可以没有 UI，但必须显式披露和启用后台能力。
  • app-enabled 或 system-event 必须声明 backgroundPolicy：版本化 triggers、不可省略的 stop、resourceClass 与 restartLimit。
  • on-demand 不需要 backgroundPolicy，调用结束后由 Host 按协议回收。
  • 用户始终能在 Extensions → Installed 查看、停止、禁用和诊断。
  • 禁用或卸载 App 必须停止全部 Component；headless 仍分别经过 SDK、Network Broker 与渠道门禁。

{ "backgroundPolicy": { "triggers": ["app-enabled@1"], "stop": ["app-disabled@1", "host-exit@1"], "resourceClass": "background-standard@1", "restartLimit": 3 } }

AI Board 01 是首个 Hardware Service Provider，不是平台启动条件

App 使用 requires.hardwareServices[] 声明 id / sdkApi / capabilities / purpose / grantDuration / optional / requiredFor。普通 UI、远程 Agent 和非硬件 Command 不得因为 AI Board 01 未连接而失效；Provider 合同以 SDK 版本为准，不以 src-tauri/、driver/ 或磁盘目录为准。

04 · Machine-readable Contract

Runtime、硬件与 requirements 合同

Component 回答“哪段代码需要它”，requiredFor 回答“用户看到哪些功能受影响”。二者必须分层。

嵌入 App Manifest 时不重复写 owner

独立 requirements 文件必须填写 owner.scope 与 owner.id；嵌入含稳定 appId 的 App Manifest 时，scope 固定继承为 app、id 继承 appId，避免两份所有者信息漂移。

依赖解析结果只保留 5 种

它们不是 App 的单一总体 status。安装中、缺少权限等具体原因放入稳定 detailCode，再映射到六维 Local State。

satisfied版本、权限、连接和完整性满足要求
needs_action依赖项需要授权、安装、下载、连接硬件、升级或重试；Host 再映射到六维 Local State
degraded有降级路径，核心流程仍可用
blocked声明中的具体功能不可用
unsupported平台或渠道不支持

Component 统一值

  • web-surface
  • wasm-component
  • remote-service
  • native-companion

影响链

Requirement → componentId → requiredFor → App。缺少必需项映射为 dependencies=missing_required；有 fallback 时映射为 dependencies=missing_optional 与 health=degraded。用户的 activation 选择保持不变。

05 · Resolution

探测、修复、逐组件降级

1读取静态声明
2解析组件与 Provider
3逐项无副作用探测
4按 componentId 汇总
5用户触发修复
6刷新 requiredFor

探测要求

  • 命令探测默认 3 秒超时，不得进入交互模式。
  • 文件探测校验路径、版本、签名或哈希，不扫描整盘。
  • Provider 先验证 id + sdkApi，再区分未安装、未连接、权限不足和驱动异常。
  • headless 健康不能只看“进程还在”，必须有心跳、超时或功能探针。

修复要求

  • 安装和下载由 Host 统一编排，用户明确触发。
  • 执行前展示发布者、来源、版本、体积、权限和卸载方式。
  • 临时目录下载，完整校验后原子替换。
  • 失败不污染已有版本，并保留重试与手动说明。

08 · Ownership

Terminal、Agent Shell 与 Hardware Provider

Terminal

  • terminal-ui 是 web-surface；PTY 是 Host Capability。
  • 系统 Shell 是 Terminal 的 os_capability。
  • Terminal 本身不依赖 Node、Python 或 Agent CLI。
  • v1.1 仅 direct；Store 构建从产物层关闭 Capability。

Agent Shell

  • 可组合 main-ui、Wasm 本地协调和 remote-service。
  • 每个 Contribution 引用实际 componentId。
  • local-cli 是可选外部工具，不是假装成 native-companion。
  • 一个 adapter 失败，仍可切换 fallback Component。

Hardware Provider

  • com.reai.hardware.board01 是首个服务，不是 App 默认启动依赖。
  • App 只通过 SDK Bridge 使用硬件，不依赖 Host 内部目录。
  • 其他键盘、麦克风或设备分别注册自己的 Provider。
  • 一个 Provider 故障不得影响另一个 Provider 或普通功能。
