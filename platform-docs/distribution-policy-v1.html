01 · What Changed

v1.1 的六个核心修正

这些是实现和评审时优先级最高的规则。

HOST唯一治理权威

Extension Registry、权限、状态、进程和 Provider 路由只有一个所有者；不绑定目录或产品名。

SDKProvider 是硬件边界

Extension 只调用 Host Capability，Host 再通过 Provider 与稳定 Hardware SDK 访问设备。

RUNTIME复合 Components

Source Manifest 使用 runtime.components[]，一个 App 可以组合 Web Surface、Wasm、远端和原生组件。

HEADLESS没有 UI 也必须可管

Headless Extension 一样要显示在已安装列表，并支持启停、授权、更新和卸载。

STATE六维状态

installation、activation、health、permissions、dependencies、update 独立保存，摘要只由 Host 推导。

VOICE推荐但可卸载

Voice 是第一方推荐 Extension，不是 required system app；卸载不能破坏平台核心。

术语：用户安装和使用的功能统一称为 App；Extension 只强调它是由 Host 安装、启停和治理的扩展单元。两者使用同一个稳定 appId，不是两套对象。
02 · Single Host Rule

一个治理中心，多种受控组件

“一个 Host”不等于“一个进程”，也不等于仓库根目录。隔离进程可以存在，但必须受 Host 监督。

REQUEST

Extension

只请求声明过的 Capability，不持有设备句柄。

ONE AUTHORITY

唯一 Host

验签、权限、生命周期、六维状态和路由。

CONTROL

Capability Gate

授权、审计、资源限制与调用仲裁。

ABSTRACTION

Provider Registry

枚举 Provider、协议、能力与健康。

DEVICE

Hardware SDK

稳定版本合同连接 USB、BLE 和未来硬件。

迁移目标

旧 root App

在能力、数据和发布切换全部验收后退役；本文不声称当前已经退役。

首个 SDK 版本

Driver

作为 SDK / Provider 架构验证载体，但不会因此被永久指定为最终 Host。

最终产品

Host 身份

由产品整合和发行决定；无论名称与目录如何，都继承唯一 Host 规则。

MUST：迁移期如果有多个可执行程序，必须通过 ownership 协议选出唯一 Host；其他程序只能作为客户端或退出。
03 · Ownership Model

开发者声明与平台政策分开

开发者说明代码需要什么；ReAI 决定是否审核通过、在哪个渠道可见、如何灰度和何时下架。

DISCOVERY

Catalog Entry

经审核的名称、版本、媒体、系统要求，以及对应 target 的 Envelope / Package 引用。

REAI OWNED

Catalog Policy

审核、渠道、灰度、价格、下架和紧急撤回；开发者不能自批。

DEVELOPER

Source Manifest

app.manifest.json 声明 hostApi.range、Components、权限、依赖、网络、计费和回滚边界。

RELEASE PROOF

Release Envelope

发布系统按 target 生成，绑定 Source Manifest 摘要、Package 摘要、buildId 与发布签名。

EXECUTION

Package

不可变、内容寻址、签名绑定的代码和资源。

LOCAL FACT

Local State

六维状态、授权、配置、失败原因和 last-known-good。

评分价格截图 / 视频分类本地化隐私说明支持入口更新日志系统要求
Source Manifest 边界：不得包含 Package 摘要、发布签名、审核状态或 Catalog Policy，也不得设置 review.status、channelEligibility、rollout、生产价格例外或强制停用策略。
Release Envelope：release-envelope.json 至少包含 envelopeVersion、identity、target、manifestDigest、packageDigest、buildId 和 signature。签名覆盖除 signature.value 外的全部字段；Package 摘要不包含 Envelope 自身。Host 固定按“Envelope 签名 → Source Manifest 摘要 → Package 摘要 → Catalog Policy”验证，任一步失败都不得解包或执行。
04 · Compound Runtime

runtime.components[]

kind 属于 Component，不属于整个 App。运行故障只改变 health 和受影响 Contribution，不能偷偷改写用户的 activation 选择。

UI SURFACEweb-surface · @1

Package 内 entry 是 ESM JavaScript；由 Host 隔离呈现，通过显式 Host Capability 完成功能。

SANDBOXwasm-component · @1

必须有 Package 内 entry，仅获得显式 Capability，并受资源配额和停止超时控制。

CLOUDremote-service · @1

必须使用 serviceRef 且没有本地 Hook；停用只撤销 Broker 会话，不代表关闭第三方服务器。

HIGH REVIEWnative-companion · @1

必须有 Package 内 entry；签名、受监督、不可自更新、提权或脱离 Host 常驻。

权限必须拆成七类

Host 能力OS 权限数据后台网络设备文件
Component 合同：公共必填字段是 id / kind / protocol / required / headless / activation；未知 protocol 版本 fail closed。本地 kind 必须写 entry，remote-service 必须写 serviceRef，二者不得并存。platforms 只能是顶层 targets 的子集，dependsOn 默认 []。Host Capability 单独写在 requires.hostCapabilities。
状态语义：activation=active 表示用户允许 Host 运行 App，不等于每个 Component 都健康；on-demand Component 可以 stopped。required 失败聚合为 health=unhealthy 并阻断核心 Contribution，optional 失败聚合为 health=degraded 并只阻断引用它的 Contribution。只有用户停用、更新切换、卸载或安全策略才能进入 stopping → disabled。
权限字段：需要用户授权的 Host、OS、后台和文件能力写入 permissions[]，每项包含 id / kind / componentId / capability / purpose / required / requiredFor / grantDuration，可选 platforms。网络、跨 App 数据和硬件分别写入 network、data、requires.hardwareServices，不得在 permissions[] 复制；Hardware Service 还要声明版本化 capabilities、purpose 和 grantDuration。
Headless：当 contributes.surfaces 为空而 Runtime Component 非空时，必须在 Extensions 标记“无界面 / 后台能力”并提供完整管理。
系统通知归属：系统通知是 OS 权限，不是普通 Host Capability。插件只能声明并调用 Host Broker；系统授权由 Host App 持有，不能因为 Host 已获授权就推定任意插件也已获用户同意。

07 · Delivery Roadmap

三阶段交付，不造三套架构

后续阶段必须复用 Platform Core 的 Host、Source Manifest、Release Envelope、状态和供应链。

当前实现目标

先把平台核心做对

  • 单一 Host ownership 与 Hardware SDK / Provider
  • Catalog Policy、Source Manifest 与 Release Envelope 分离
  • runtime.components[]、Headless、七类权限、六维状态
  • Extensions 已安装管理；基础 Browse Extensions 只展示本次 Host Release 已审核第一方内容
  • Voice 是推荐、可卸载政策；真正接入前先定义版本化 Voice / Media Capability
本阶段不依赖远程 Feed 或第三方 Marketplace 才能工作，也不能调用未定义的 Voice / Media 接口。
第二阶段

官网签名分发

  • 签名 Catalog Feed 与按需 Package
  • Host / Extension / 资源三通道更新
  • last-known-good、防回滚、灰度与紧急撤回
  • 新 Extension 独立发布门禁
  • 独立 developer_local Profile 与受控本地导入
Developer Mode 必须持续显示“未经过 ReAI 审核”，且不能关闭 Sandbox 或权限门禁。
第三阶段

第三方 Marketplace

  • 开发者提交、源码审核、受控构建与签名
  • Browse Extensions 增加公开第三方搜索、评分、付费、推荐与运营
  • 价格、授权、地区/年龄、举报、下架与争议处理
  • 发布者身份、复审与安全响应 SLA
Marketplace 不能创建第二个 Host，也不能让 Source Manifest 获得 Catalog Policy 权限。
08 · Channel Profiles

三条生产发行通道

商店版目录随 Host Release；Direct 在第二阶段通过签名 Feed 独立更新。

Mac App Store

  • Catalog 成员随 Host Release 提交审核。
  • 可执行 Package 随 App Bundle 交付，用户按需启用。
  • 非执行模型与媒体可按需下载并验证摘要。
  • Host 只通过商店更新，遵守 Sandbox，不提权、不留未授权常驻进程。

Microsoft Store

  • Catalog 成员随 Host Release 认证。
  • v1.1 默认随主包交付可执行能力。
  • Optional Executable Package 需 Store 许可、Related Set、签名与独立 Profile 升级。
  • 非 Microsoft 驱动或 NT Service 不作为普通 Extension。

ReAI Direct

  • 生产 Host 需平台认可的签名；macOS 直发完成公证。
  • Feed 使用 HTTPS、整体签名、单调版本、防回滚和 last-known-good。
  • 新 Extension 可独立发布，但必须通过全部门禁。
  • Developer Mode 使用独立 developer_local Profile：显式开启、逐包导入、持续未审核提示、一键停用。
本地导入不是审核：不得获得生产 Catalog 标识、生产计费权益、静默自启或安全门禁豁免。

10 · Lifecycle

审核一次，组件按图启停

Package 先 staging；Host 完成 Envelope、Source Manifest、Package 和 Catalog Policy 验证后，再按依赖图运行 Component。

1审核源码、Source Manifest、Policy、权限
2受控构建锁依赖、SBOM、Manifest / Package 摘要
3签名发布生成 Release Envelope 与独立 Catalog Policy
4验证启用staging、固定顺序验签、依赖图启动
5监测回滚健康门槛、逆序停止、LKG
MUST：停用时先阻止新调用，再按组件依赖逆序停止；Host 退出后 Headless / Companion 也必须停止，除非有单独且可撤销的常驻授权。
11 · Rule Explorer

筛选 v1.1 规则

可按主题或关键词快速定位发送给合作方的规则。

显示 14 条规则

MUSTHOST-01

Host 是规则，不是目录

一个平台实例只能有一个 Registry、权限权威、状态所有者和 Provider 路由中心。

MUSTHOST-02

设备访问经过 Provider

Extension 只请求 Host Capability，不依赖 Driver 内部模块或持有底层设备句柄。

PLANHOST-03

迁移目标不冒充现状

旧 root App 退役需等迁移验收；Driver 是首个 SDK 规划版本，不是永久最终 Host。

MUSTMANIFEST-01

使用 runtime.components[]

kind 与 protocol 属于 Component；required 失败聚合 unhealthy，optional 失败聚合 degraded，都不改写 activation。

MUST NOTMANIFEST-02

Source Manifest 不含发布证明

Package 摘要和签名只在 Release Envelope；审核、渠道、灰度、价格与下架只在 Catalog Policy。

MUSTMANIFEST-03

Headless 同样受管

没有页面也必须可安装、启停、授权、更新、回滚和卸载。

MUSTPERM-01

权限按所有权分字段

Host、OS、后台、文件进入 permissions[]；网络、跨 App 数据、硬件分别进入 network、data、requires.hardwareServices。

MUSTPERM-02

扩大范围重新授权

新增类别或扩大范围必须重新审核、签名，并让用户再次明确同意。

MUSTSTATE-01

六维独立保存

用户摘要由 Host 单向推导，不反向成为状态机输入。

MUST NOTSTATE-02

Extension 不可自报总体健康

Component 可提供观测，只有 Host 能聚合并持久化 Extension health。

MUSTCHANNEL-01

商店目录锁定 Host Release

Mac / Microsoft Store 新成员随下一次 Host 提交，不用 Feed 静默增加。

MUSTCHANNEL-02

本地导入使用独立 Profile

持续显示未审核来源，不继承生产权益，也不能关闭 Sandbox 与权限门禁。

MUSTUX-01

发现与唯一管理分离

Browse Extensions 只负责发现、详情和安装；Extensions 是唯一管理入口，默认 Installed 并包含 Headless。

MUSTUX-02

Voice 可卸载

推荐安装不等于系统必需；移除 Voice 后 Host、Provider 和 Extensions 管理仍正常。

13 · Acceptance
