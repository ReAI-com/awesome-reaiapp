00 · 先说人话

开发者只管右侧 App 空间

左侧壳层由 Host 管。App 声明入口、渲染自己的 Surface，并把动作注册成 Command。

一个 ReAI App 做三件事：用 Manifest 说明“我是谁”，在 Host 给出的右侧工作区画自己的界面，再注册 Command 让鼠标或硬件能调用功能。

Host 是架构规则，不是某个目录：未来唯一桌面 Host 通过每款硬件自己的 SDK / Provider 接入设备。当前根目录产品计划退役，driver/ 是首个 SDK 探索；开发合同不绑定二者。AI Board 01 只是可选增强，没有它 App 也能走普通软件与键盘逻辑。

01 / MANIFEST

声明入口

名称、图标、侧栏项、Surface、Command、权限和兼容范围。

02 / SURFACE

渲染界面

只在 Host 给出的 root 内工作；页面、列表和局部抽屉归 App。

03 / COMMAND

接收动作

侧栏、按钮和硬件最终都调用有稳定 ID 的 Command。

import { defineApp, AppError } from "@reai/app-sdk/v1";
import { mountTodoView } from "./todo-view";

export default defineApp({
  async activate(ctx) {
    const tasks = ctx.storage.private("tasks");

    ctx.commands.register("com.example.todo.new", async ({ signal }) => {
      await ctx.surfaces.open(
        "main",
        { intent: { type: "new-task" } },
        { signal },
      );
      return { status: "ok" };
    });

    ctx.surfaces.register("main", async (surface) => {
      let items;
      try {
        items = (await tasks.get("items")) ?? [];
      } catch (cause) {
        surface.fail(new AppError({
          code: "com.example.todo/STORAGE_READ_FAILED",
          userMessage: "无法读取待办事项",
          retryable: true,
          cause,
        }));
        return;
      }

      let view;
      let offIntent;
      try {
        const mountedView = mountTodoView(surface.root, {
          items,
          onItemsChanged: (next) => tasks.set("items", next),
          onPersistenceError: (cause) => surface.reportError(new AppError({
            code: "com.example.todo/STORAGE_WRITE_FAILED",
            userMessage: "保存失败，请重试。",
            retryable: true,
            cause,
          })),
        });
        view = mountedView;

        const applyIntent = (intent) => {
          if (intent?.type === "new-task") mountedView.focusNewTaskInput();
        };
        applyIntent(surface.initialIntent);
        offIntent = surface.onIntent(applyIntent);

        surface.ready();
      } catch (cause) {
        offIntent?.();
        view?.dispose();
        surface.fail(new AppError({
          code: "com.example.todo/SURFACE_INIT_FAILED",
          userMessage: "无法打开待办事项",
          retryable: true,
          cause,
        }));
        return;
      }

      return () => {
        offIntent?.();
        view?.dispose();
      };
    });
  },

  async deactivate() {
    // 清理 App 自己创建的计时器、连接和观察器。
  },
});
export function mountTodoView(root, options) {
  let items = [...options.items];
  let saving = false;
  let disposed = false;
  const page = document.createElement("main");
  const form = document.createElement("form");
  const input = document.createElement("input");
  input.id = "todo-new-task";
  input.name = "todo-title";
  const add = document.createElement("button");
  const list = document.createElement("ul");
  const status = document.createElement("p");

  input.placeholder = "要做什么？";
  input.setAttribute("aria-label", "新待办内容");
  add.type = "submit";
  add.textContent = "添加";
  status.setAttribute("role", "status");
  form.append(input, add);
  page.append(form, status, list);
  root.replaceChildren(page);

  const save = async (next) => {
    if (saving || disposed) return false;
    saving = true;
    status.textContent = "正在保存…";
    render();
    try {
      await options.onItemsChanged(next);
      if (disposed) return false;
      items = next;
      status.textContent = "已保存";
      return true;
    } catch (cause) {
      options.onPersistenceError?.(cause);
      if (!disposed) status.textContent = "保存失败，请重试。";
      return false;
    } finally {
      saving = false;
      if (!disposed) render();
    }
  };

  const render = () => {
    input.disabled = saving;
    add.disabled = saving;
    list.replaceChildren();
    for (const item of items) {
      const row = document.createElement("li");
      const toggle = document.createElement("input");
      const label = document.createElement("span");
      toggle.type = "checkbox";
      toggle.checked = item.done;
      toggle.disabled = saving;
      label.textContent = item.title;
      toggle.addEventListener("change", () => void save(
        items.map((current) => current.id === item.id
          ? { ...current, done: toggle.checked }
          : current),
      ));
      row.append(toggle, label);
      list.append(row);
    }
  };

  const onSubmit = async (event) => {
    event.preventDefault();
    const title = input.value.trim();
    if (!title) return;
    const saved = await save([...items, {
      id: crypto.randomUUID(),
      title,
      done: false,
    }]);
    if (saved) input.value = "";
  };

  form.addEventListener("submit", onSubmit);
  render();
  return {
    focusNewTaskInput: () => input.focus(),
    dispose() {
      disposed = true;
      form.removeEventListener("submit", onSubmit);
      root.replaceChildren();
    },
  };
}

COMPOSITE RUNTIME

一个 App 可有多个组件

组件固定声明 id / kind / protocol / required / headless / activation；web-surface@1 入口统一为 ESM JavaScript。

HEADLESS

无页面也能管理

没有 Surface 的 App 仍出现在 Extensions → Installed，可查看状态、权限、错误并启停或卸载。

PERMISSIONS

能力不等于授权

Host、OS、数据、后台、网络、硬件和文件七类分项授权；能力存在不代表用户已经同意。

{
  "id": "voice-microphone",
  "kind": "os",
  "componentId": "voice-worker",
  "capability": "os.microphone.capture@1",
  "purpose": "录制用户主动发起的语音输入",
  "required": true,
  "requiredFor": ["command:voice-capture"],
  "grantDuration": "while_enabled",
  "platforms": ["macos", "windows"]
}

permissions[] 只承载需要用户授权的 Host、OS、后台与文件能力；网络、数据共享和硬件使用各自的结构化声明。grantDuration 只允许 once / session / while_enabled / until_revoked，用户始终能撤销。

授权必须由用户发起

通知调用依次经过有效会话、Manifest 声明、当前插件的用户授权和系统通知授权。Host 启动只查询、不申请；macOS 用户必须点击首次引导中的“开启通知”或设置页的“允许通知”才会请求系统授权。首次未决定时直接弹出系统确认；已拒绝后只能由用户从系统设置重新开启。

标题最多 80 字符、正文最多 500 字符；Host 加入插件名与 appId 指纹，每插件每 10 秒最多发起 5 次通知请求。{ queued: true } 只表示加入本地发送队列。

Windows/其他非 macOS 构建当前暂由 Host 视为系统通知已授权，但插件自己的 Manifest 声明与用户授权仍不可省略。appId 指纹用于追踪来源；插件显示名不是可信发布者身份。

v1.1 Contribution Registry
贡献负责什么关键规则
surfaces / sidebarItems页面与侧栏入口页面代码绑定 componentId
commands / intents动作与跨 App 跳转输入输出有版本、Schema、超时和调用方
recommendedBindings普通快捷键与硬件控制项建议只贡献建议，不覆盖用户有效绑定

安全边界：每个 App UI 必须运行在独立 renderer / security origin；surface.root 属于该隔离文档。App 拿不到 Host DOM、Tauri 原生命令或直通网络，只能通过带 App 身份和 Capability 的 SDK Bridge 调用 Host。

v1.1 最小 Sandbox 合同
项目默认规则
CSPdefault-src 'self'、connect-src 'none'；禁用 eval，网络只走 Broker。
导航 / 下载只允许同源导航；外部 HTTPS 由 Host 确认；下载默认拒绝并走 Export Capability。
剪贴板 / 文件只能用 Broker；文件选择返回有范围、可撤销的 Handle。
Worker只加载同 Package、同 security origin 的代码，并计入 Component 资源预算。
Bridge目标合同为双向 1 MiB 与可取消调用；当前只对 Host→插件事件执行 1 MiB，插件→Host 请求和 Host 超时取消仍待补齐。
身份 / 崩溃Host 注入不可伪造的 App、Component 与 Session 身份；组件崩溃不拖垮 Host。
Surface 嵌入合同
项目v1.1 规则
尺寸Host 提供右侧工作区视口；App 根节点填满可用宽高，不假设固定窗口尺寸。
滚动App 只管理自己 Surface 内的滚动，不能推动 Host 侧栏或窗口根节点。
主题Host 通过版本化 CSS Token 与 color-scheme 提供主题；App 不读取 Host 样式表。
ResizeApp 监听自己根节点的 ResizeObserver 做响应式布局，不依赖 Host DOM 尺寸。
焦点普通打开不抢焦点；只有明确 intent（如“新建待办”）才聚焦指定控件。
浮层App 内 Dialog / Popover 留在隔离 Surface；系统权限、设备和账号浮层由 Host 绘制。
导航App 登记自己的局部导航层；Esc 先关闭最内层，再交还 Host。

surface.navigation.pushLayer() 与非致命诊断的 surface.reportError() 都属于 surface.main@1 子合同，不是额外权限，也不需要在 Manifest 重复声明；它们是 Design v1.1 目标接口，当前尚未实现。

05 · 生命周期

点一个阶段，看谁调用谁

安装、启用、打开和卸载不是一个动作。Host 负责状态机，App 只响应明确的运行时回调。

PACKAGE · NO CODE

安装：只验证和落盘

安装阶段不执行 App 代码。Host 按 Release Envelope 验证签名、Source Manifest 摘要、Package 摘要、兼容性与渠道政策。

触发用户在 Browse Extensions 点击“安装”
Hostverify → stage → registry commit
App无回调；禁止 onInstall 脚本
Registry commit 后 installation=installed、activation=disabled；不执行代码，也不自动跳进 App。
Core 保存六个正交状态；界面摘要由它们推导

dependencieschecking / ready / missing_optional / missing_required / incompatible硬件与系统依赖是否满足

为什么进入 Core：“已安装、未启用、缺权限、某组件降级、有更新”可以同时成立。activation=active 只表示用户允许 Host 运行 App；按需组件仍可 stopped。required 组件失败聚合为 health=unhealthy，optional 组件失败聚合为 health=degraded，故障不能偷偷改写用户的启用选择。

    插件与硬件解耦（2026-08-16 架构拍板）：上一条 M6 的落地语义在这次拍板中升级成架构红线，适用于所有插件、所有硬件——合同面只有插件暴露的事件（contributes.commands，跨插件入口是 contributes.intents），硬件要触发插件只能触发这些事件——这里的「事件」特指硬件到插件的可绑定动作，跟 contributes.eventSubscriptions（Host 到插件的订阅）不是同一件事；按键 / 拨杆 / 旋钮与事件之间的映射归 Host 键位设置持有和管理，插件既不声明也不读取这层映射。插件不得内置硬件绑定逻辑，不得假设某款硬件存在（含 AI Board 01），也不得因为缺少该硬件而整体失效；插件设置页也不得出现「按哪个键触发我」这类绑定配置——那是键位设置的界面，出现在插件里就是耦合。理由很直接：以后还会有别的硬件，穷举硬件行为不现实，让插件暴露事件、让硬件去触发事件，键盘的事留在键盘自己那边。拨杆的分层覆盖模型（CHAT / YOLO / PLAN 三档各算一层，档位层覆盖通用层）是 Host 键位系统自己的规格，不进入插件合同——插件只会收到自己那条事件被调用，看不到也不需要看到这套分层。

    surfaces.open 的真实语义是幂等 reveal（M6.1）：合同是「让我的主界面被看见」——已挂载则主窗口前置聚焦、Host 前端跳到该 App 的扩展页、携带的 intent 按 surface.intent 信封投递给当前 mount，返回 { accepted: true }；Command 拉起界面时同样「跳到现场」，界面由扩展页接管落位/关闭/Esc。只有开自己没声明的界面才拒绝（HOST_CAPABILITY_NOT_AVAILABLE，首版矩阵限单个 main）；「窗口在、登记不在」的中间态会得到说明原因的拒绝文案。Host 拒绝在 SDK 进门处归一为 AppError（userMessage 取 Host 文案），不再退化成「扩展遇到未处理的错误」。onIntent 注册前到达的 intent 由 SDK 为每个 mount 缓冲最近一条、注册时补发（unmount 即清），App 不需要自己防丢。

    09.5 · 平台机制（2026-08-12 同步）

    能力授予、标题栏动作、插件权限、Tab 层与 Action 广播

    通用平台机制由所有插件共用——不是某个插件的专属 UI。系统通知同样只能通过 Host Broker。完整合同见 Markdown 版第 11 章。

    GRANTS

    能力授予分档

    grantGated 是需按 appId 授予的官方窄能力（Codex、startup、Voice Input / Command）。titlebar.action@1 属于通用 granted：生产 Catalog 仍受 official-only 分发限制，Developer Mode 本地插件可按同一合同使用。

    TITLEBAR

    Host 托管状态与动作

    titlebarActions 最多 3 个，支持默认、描边与危险动作；可选 titlebarStatus 显示静态状态胶囊。Host 只渲染白名单图标与纯文本。省略或关闭 showOnTitlebarHover 时常驻，适合设置等需持续可发现的入口；开启后仅在整条 44px 标题栏 hover 或键盘 focus 时显示，适合低频辅助动作。点击按当前 presentation 投递 Manifest intent，切换、停用或卸载自动清场。source 是 Host 保留字段，peer App 不能通过普通 intent 伪造同形点击。

    TAB

    Tab 层实体条目

    声明 contributes.tabItems 后经 ctx.tabItems.upsert 供给：同实体重推只重排不产生第二条；requiresInteraction 只许配 waiting_input（举旗门禁）；停用/卸载清场、回收保留。Tab 层是全局置顶浮窗（Tab 键默认唤起），条目零决策、点击只跳转。

    EVENTS

    事件订阅与广播

    eventSubscriptions 声明即订阅（mount 关闭即退订），v1 仅 actionContext，SDK 侧 ctx.events.on。Action 上下文广播=数据向下（声明 acceptsActionContext 才收），存证走 TTL/容量自动清理 + 一次性取件 token（ctx.evidence.fetch）；Action 菜单=动作向上单选（Action 键默认唤起，实时聚合、选中只有那条执行）。

    通知 Broker 做什么

    • 校验插件会话、安装与启用状态。
    • 校验 Manifest 和当前插件的用户授权。
    • 只读检查系统通知授权，不替插件弹授权框。
    • 加入插件来源指纹、校验负载并执行速率限制。

    插件不能做什么

    • 不能在 App 启动或插件调用时触发系统授权。
    • 不能绕过 Host 调 Tauri notification JS API。
    • 不能移除 Host 注入的来源标签；显示名本身不代表可信发布者。
    • 不能把 queued: true 当成用户一定看到。

    稳定失败：系统通知尚未决定或已拒绝时分别返回 SYSTEM_NOTIFICATION_PERMISSION_REQUIRED / SYSTEM_NOTIFICATION_PERMISSION_DENIED；状态不可读、速率超限、负载非法和入队失败也都有独立错误码。插件必须给出可执行说明，不能循环重试或自行申请系统授权；完整错误表见 插件接口参考。

    10 · 最佳实践

    边界清楚，开发才会简单

    Design 原型内部函数不是公开 SDK。产品实现要使用 Host 合同，不要复制原型 DOM 技巧。

    界面克制：只显示此刻要紧的那件事

    这是全局设计哲学，优先于下面所有具体条目。一个功能做得再对，出现在不该出现的时刻，它就是干扰。一句话：根据用户当前的场景和需求渐进披露，不要把所有东西堆到一起。用户在一个时刻只关心一件事，界面要替他把别的收起来，而不是把选择权连同认知负担一起丢回去。下面五条是它的可执行判据。

    1
    无必要，勿增按钮能自动发生的事不要做成开关。判据：不给这颗按钮，用户会失去什么？如果什么都不失去（那件事本来就会自己发生），它就只剩负担。日程页 V1.3 撤掉的「日历展开」与「日程助理」都属此类——点日期日历自己会开，助理该出现时自己会来。注意同一颗按钮在不同尺寸下必要性可能不同：日历按钮宽屏多余、窄屏必要，所以它只在窄屏出现。
    2
    全局能力不在单个 App 里开第二个入口提醒、通知、待办这类「有事要你处理」是全平台共有的语义。每个 App 各开一个铃铛，用户就得挨个 App 巡一遍——注意力被切成 N 份。App 只负责把事件记进 Host，不自己造呈现入口；自己那一侧的出声方式是让相关界面在相关时刻自己出现（助理主动来问），而不是在角落点亮小红点等用户发现。
    3
    留白是用来分组的，不是装饰相邻两块如果回答的不是同一个问题（「我在看哪天」和「我要做什么」就是两个问题），它们之间必须有明显大于组内间距的留白。Host 注入 --reai-plugin-titlebar-safe-top（macOS 44px、其他平台 0px），App 根框架只消费一次；正文里的留白仍按语义分组，不能在安全区下面再堆一层装饰性空白。顶部交界只允许“同色连续”或“异色内缩”：同色时使用同一主题背景且不加装饰性间距；异色时把第一块 Surface 内缩到 main-body，桌面默认 16px、紧凑布局最低 12px。禁止两个不同颜色的全宽大色块零距离硬切，1px 分割线不算留白。
    4
    按钮的长相由设计系统给，不由浏览器给任何 <button> 只要样式没写全，浏览器默认的灰底黑框就会顶出来。这不是某一处写漏了，是缺一条地基：样式表必须有全局按钮基线，把 border / background / font / color 归零，视觉一律由 class 显式给出，:focus-visible 的可见描边保留。同层级操作用同一套按钮语言，Review 判据是——遮住页面其余部分单看这颗按钮，说得出它属于哪一档吗？
    5
    渐进式披露：先收下，再补全输入流程不要一上来铺开完整表单。先拿到最少必要信息把事办成，其余做成按需展开的可选补充。日程页新增流程是样板：入口收成一颗按钮 → 点开铺满整页（此刻别的都不重要，所以别的都不在）→ 默认语音待命，敲键盘即转打字 → 属性只是一排图标，点哪个展开哪一条 → 收下后缺信息由助理自己来问。「可以不理」必须真的零代价：追问时不顶开详情、不抢焦点、不挡住原本在看的东西，否则「不理它」就变成了「先退出来再说」。
    button{font:inherit;color:inherit;border:0;background:transparent;cursor:pointer;
       -webkit-appearance:none;appearance:none;text-align:inherit}
button:focus-visible{outline:2px solid var(--accent);outline-offset:2px}

    工程边界

    应该这样做

    • 只在 surface.root 内渲染。
    • 第一屏真正可用后再调用 ready()。
    • 每次 mount 都返回完整 cleanup。
    • 用 Manifest 静态声明侧栏和 Command。
    • 推荐键位交给用户确认。
    • 错误提供稳定 code、可执行动作和 trace。
    • 样式表先立一条全局按钮基线，再由 class 给长相。
    • 能自动发生的事就让它自动发生，不做成开关。

    不要这样做

    • 修改侧栏、Browse Extensions、设备卡或账户 DOM。
    • 在自己 App 里另开通知、提醒等全局能力的入口。
    • 一上来铺开完整表单，把所有字段堆给用户。
    • 调用原型里的 setV()、VIEWS、rail-slot。
    • 刚开始执行就 ready，之后给用户看白屏。
    • 偷偷启动 npm、Python、Shell 或常驻进程。
    • 监听整个窗口并吞掉 Host 的 Esc。
    • 用远程配置下载或解释新的可执行逻辑。
