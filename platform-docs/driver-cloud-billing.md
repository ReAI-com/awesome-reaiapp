# Driver 订阅、积分与云服务

Driver 的云服务支持按量使用：**没有订阅也可以消耗积分，积分不足时由服务端拒绝请求。** 订阅不是云模型、联网搜索、网页抓取或云识别的统一使用门槛。正常的登录、权限、项目访问和服务健康检查仍然适用；有积分不保证任意请求都能成功。

本文描述接入按量付费版本的行为。旧客户端需升级到包含此功能的版本；文档更新或代码合并不代表安装包已发布。插件更新通过各自的发布流程交付。

## 订阅与积分如何配合

| 情况 | 行为 |
|---|---|
| 没有订阅或订阅到期 | 仍可进入按量计费，由具体请求检查积分是否足够 |
| 有有效订阅 | 显示订阅权益，继续服从服务端实际计费和可用性规则；不代表免费或无限使用 |
| 积分不足 | 服务端计费拒绝，不应提示购买订阅；补足对应计费团队的积分后重试 |
| 订阅或余额读取失败 | 页面显示未知或错误，不伪装成无订阅或零积分；页面快照不控制云请求准入 |

本地功能和用户自己的 Desktop 账户不受此订阅页限制。Driver 订阅状态也不代表第三方插件商品的购买状态。

## 查看订阅和余额

从 Driver 左下角账户菜单打开「订阅」。页面显示默认个人团队的订阅、最近账单及积分余额；没有套餐时说明仍可按量使用。余额包括赠送和购买两部分，账期截止不表示所有购买积分到期。

展开「方案详情」可查看真实方案介绍、权益、当前周期及可确认的下一期。每个团队只有一个套餐；某个套餐是否包含 Driver 权益由服务端判断，包含时会明确显示，无需把它理解为另买了一份 Driver 订阅。不同团队的套餐和积分各自独立。

「本期赠送额度」是这一期的总额度，「订阅赠送积分（剩余）」是尚未消费的余额；本期积分还在发放时会单独提示，不会提前加到可用余额。只有已经付款且允许生效的下一期才显示按期生效；未付款意向、付款未知和已付但生效受阻会分别提示。服务端明确返回不自动扣款时，页面会显示续购需手动支付；缺少此信息时不会自行承诺付款方式。

到期安排与停止续订的生效日可能不同：如果下一期已经付过款，停止后续续订不会让该已付周期消失。具体日期与行为以页面的服务端结果为准。资料暂不可确认时显示未知；介绍被摘要长度限制裁剪时会提示通过浏览器管理页查看完整内容。旧后端缺少新字段时只显示其能确认的信息。

只显示**默认个人团队**的余额。项目服务（例如联网搜索、抓取）可能扣项目所属团队，不能用当前页面余额推断所有项目的可用额度。最终费用和余额是否足够，以具体请求的服务端计费为准。

充值或管理订阅使用页面中的网页管理入口，在浏览器中正常登录对应账户和团队。Driver 不自行生成付款地址，也不在网页 URL 中携带 OAuth token。

## 升级后提示重新授权

新版 Driver 需要只读权限 `billing:read`。旧会话不会因为客户端升级自动获得新增权限：

1. 在 Driver 的「账户」中退出当前会话，再正常登录。
2. 核对授权页的应用与账号，确认权限中包含「读取订阅与账单摘要」。
3. 返回 Driver，重新打开「订阅」并刷新。

若提示应用定义已变化，重新发起一次授权以读取新的应用定义。若反复失败，记录错误码并联系支持，不要反复购买订阅或重置密码。若提示当前版本未启用订阅读取，则需升级客户端；仅重新登录不能补上构建时缺失的能力。

## 插件开发者须知

- `billing:read` 是正式 Driver 的受限 OAuth 权限，**不是普通插件可申请的公开余额 API**。本次没有新增插件 SDK 的订阅或余额接口。
- 插件使用既有云能力及权限声明；不要读取 Host 凭据、直接调用内部账单接口，或按套餐名称、余额快照自行增加订阅门禁。
- Host 的 `GET /billing/summary` 将余额整数以毫积分传输：`1000 毫积分 = 1 显示积分`。此处说明展示单位，不授权插件访问该接口。缺失、null 或非法余额是未知；0 和有效负余额保留真实含义。
- 处理额度不足时引导补充正确团队的积分。处理 `AI_SUBSCRIPTION_REQUIRED` 或 `web_access_subscription_required` 等旧后端兼容错误时，说明服务端尚未开放按量能力，不要要求先购买订阅。其他网络、限流或服务故障分别按 [云错误合同](./plugin-api-reference-v1.md) 处理。
- 订阅权益占位字段不代表已获得权益，`cloudAccess` 表达订阅权益状态，不是所有云请求的准入开关。

## 云转写的当前价格（源码候选）

转写设置展示的是已认证当前账号的有效美元美分/秒，而不是永久免费标签。数值0仍产生用量与金额0的账证，记录订阅原因及价格版本；订阅政策的有效价格变为0.1时，普通请求正常计费。没有可信当前报价时显示不可用，不按模型名称、默认项或套餐名猜测。

`isDefault` 只表示当前默认选项，可以免费也可以收费。已有明确的 `free-only` 选择及录音重试保留免费限定，价格变更后拒绝执行；明确选择不同选项采用新项的普通策略。录音快照和重试不会因为页面刷新自动丢掉原约束。服务端最终执行报价与账证为准，设置页报价不承诺未来永远为0。

Host 每次读取私有报价，响应必须同时包含 `private` 和 `no-store`。该 GET 从配置读取入口起共用 15 秒预算，包含一次 401 凭据刷新等待、重发、响应头、body 和解析。截止后先复核当前凭据与插件授权：会话、绑定、权限或调用代次已失效时返回对应错误，否则返回 `AI_TIMEOUT`；均不进入音频 POST。配置读取失败时，模型列表仍可保留已取得的文本档位。不缓存报价、不猜价，也不转用付费选项。

初始插件凭据获取不在该配置 GET 的预算内，音频 POST 仍使用原有超时；这不保证整个转写调用在 15 秒内结束，也不改变取消墓碑的 60 秒 TTL。配置截止结束调用方的读取与刷新等待，凭据收尾按实际来源和阶段区分：

- 当前私有 ASR 配置读取只使用插件凭据。通用云请求的 Host 来源（`CloudCredentials::Host`）401 快照刷新没有账户任务接管；其未完成的刷新 future 可随调用方截止丢弃，并释放本地凭据锁。远端可能已轮换 token，本地尚未收到完整响应；此时结果未知，截止本身不触发自动重试或清除凭据。之后的正常请求可能需要重新授权。
- 插件来源（`PluginCloudAuthorization`）先再验证 metadata，再取得插件凭据并按需续期。metadata 请求和凭据锁等待仍在调用方内，可随截止取消；尚未开始的排队刷新也可被跳过。开发模式的 metadata 再验证可能先通过同一个 owner 轮换 Host token，因此不能把所有 Host token 轮换都视为上述无 owner 路径。
- 已开始的插件云凭据 token HTTP 到原会话核验提交，由原账户的 `AccountTasks` 拥有。截止只丢弃等待方，正在进行的这次轮换按 OAuth 客户端自身 HTTP 超时收尾，凭据锁保留到收尾结束。尚未开始的 metadata、后续凭据阶段和业务重发不会因此继续。账号退休拒绝新入场，并等待已开始的轮换结束后排空原租约；会话核验拒绝把迟到结果写入新会话。

该收尾不保证 token 轮换成功；自身 HTTP 超时或响应丢失仍可能留下未知结果。它不延长配置 GET，也不启动音频 POST 或生成请求，不承诺整个收尾恰好在 15 秒内完成。临时失败保留凭据，明确拒绝才按既有合同处理；配置截止本身不新增重试或清理。账号退出和插件代次变化仍按原合同拒绝旧请求。

后台模型表刷新与录音预热采用各自的任务生命周期，不随调用方或界面叫停中途丢弃凭据及模型表请求。网络请求仍有自身超时；完整续期响应仍按 AuthState 的会话核验提交，已叫停的预热不公布模型表结果。私有 ASR 配置 GET 的统一预算约束调用方的等待，不取消已开始的账户任务轮换；该轮换按自身 HTTP 超时及原会话提交合同收尾，也不保证配置读取成功。
