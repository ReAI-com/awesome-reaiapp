01 · BASELINE

三条不可绕过的主线

Source Manifest 是开发者的公开承诺，Release Envelope 把审核结果绑定到发布包；用户同意是当前授权，运行时执行才是最终边界。 只做其中任何一层，都不足以形成可信平台。

N

网络默认拒绝

未声明目标直接阻止。域名、用途、数据、留存、鉴权或服务商发生扩大时，重新审核并重新取得同意。

B

支付默认托管

App 只能调用 Billing Broker。外部支付是可撤销的高权限例外，不是插件自行实现后的轻度提示。

D

跨 App 默认隔离

数据默认只在 App-ID 私有 Store。v1.1 只允许同一签名 Publisher 的 App 通过双边合同、用户同意与 Host 审计共享。

一句话判断

远端只返回数据，App 不持有秘密或他人 Store；Host 掌握网络出口、跨 App Data Handle、商品价格、支付通道与最终权益。direct 的官方 local_cli 按外部应用单独披露。

02 · DELIVERY LEVELS

合同、直发与市场是三个阶段

本页定义实现目标和未来准入规则，不把尚未上线的 Marketplace 描述为 Core 已有能力。

CORE · v1.1

Platform Core

Component 身份、四类 Broker、私有 Store、授权、错误与审计合同。状态：已锁定的实现目标。

CHANNEL · direct

Direct Distribution

ReAI 签名直发、官方 local_cli 例外和 ReAI Billing。相关 Core 门禁完成后才能逐项启用。

FUTURE · marketplace

Marketplace

未来的 Publisher 入驻、公开审核、Catalog、销售、退款和处罚。本文条款是准入条件，不是上线声明。

03 · COMPONENT IDENTITY

能力授予具体 Component，不授予模糊的“整个插件”

每次网络、数据和计费调用都绑定 Release Envelope 确认的运行时身份。

Source Manifest + Release EnvelopeComponent 合同
appId + componentId + publisherId + packageDigest + componentKind

      "id": "main-ui",
      "kind": "web-surface",
      "protocol": "web-surface@1",
      "required": true,
      "headless": false,
      "activation": "on-demand",
      "entry": "dist/app.js",
      "lifecycle": {
        "activate": "default.activate",
        "deactivate": "default.deactivate"
      }
    }, {
      "id": "cloud-sync",
      "kind": "wasm-component",
      "protocol": "wasm-component@1",
      "required": false,
      "headless": true,
      "activation": "app-enabled",
      "entry": "runtime/cloud-sync.wasm",
      "lifecycle": {
        "activate": "exports.activate",
        "deactivate": "exports.deactivate"

ID

权限不串用

一个 Component 不能借用另一个 Component 的网络、Data Handle 或 Billing 能力；同进程也要分离逻辑身份与审计。

↓

独立降级

可选 Component 失败时 Host 聚合 health=degraded；必需 Component 失败聚合 health=unhealthy，并按原因更新 dependencies 或 permissions。

Composite Runtime 状态

Host 同时展示 App 总体状态和 Component 级状态；新增 Component、改变 componentKind，或把能力迁到更宽权限 Component，都属于权限扩大。componentId 必须来自 Release Envelope 绑定的 Source Manifest。

04 · NETWORK GATES

请求放行前要过四道门

任意一层失败，请求都不能退回到插件自行联网。

1. 声明Source Manifest 写清目标、用途、数据、留存与鉴权。
2. 审核Release Envelope 把源码审核、产物摘要与声明绑定。
3. 同意当前安装实例已授权这一组能力。
4. 执行Host 校验 URL、重定向、凭据和实际载荷。
远端响应不是新代码

禁止加载远端脚本、Wasm、二进制、Node/Python 包或 Shell。远端配置只能选择已审核包中已有的有限分支。

外部 CLI 是收窄例外，不是第二条插件网络通道

Claude、Codex、Kimi 等独立进程只能由 direct 的官方 Adapter 调用。Host 可记录启动与交付数据，却不能声称代理或审计了它们的全部出站请求；Store Profile 不开放 local_cli，普通第三方 App 也不得借 CLI、Shell、curl 或浏览器绕过 Network Broker。

05 · MANIFEST

一次声明回答十个问题

哪个 Component、去哪里、谁运营、为什么、发送什么、保存多久、是不是必需、能不能替换、怎样鉴权，以及声明版本。

Source Manifest · network v1示例
{
  "network": {
    "policyVersion": 1,
    "endpoints": [{
      "id": "model-api",
      "componentId": "cloud-sync",
      "origins": ["https://api.example.com"],
      "owner": "publisher",
      "purpose": ["inference"],
      "dataCategories": ["user_prompt", "model_response"],
      "retention": {
        "mode": "provider_policy",
        "maxDays": 30,
        "policyUrl": "https://example.com/privacy"
      },
      "required": false,
      "providerMode": "user_configurable",
      "userConfiguredOrigins": {
        "allowed": true,
        "maxOrigins": 3
      },
      "auth": {
        "mode": "host_credential",
        "credentialSlot": "model-api-key"
      }
    }]
  }
}
字段允许值 / 内容运行时意义
componentIdruntime.components 中的稳定 ID网络能力、失败状态和审计都归因到具体 Component。
origins精确 HTTPS / WSS origin未命中、端口变化和跨域重定向全部阻止。
ownerreai / publisher / third_party / user_configured告诉用户数据真正交给谁。
purposeinference / auth / storage / sync / assets / telemetry / billing / support实际用途超出声明即违规。
dataCategories提示词、文件、转写、账号标识、诊断等新增类别属于权限扩大。
retentionnone / session / fixed / provider_policy必须有结构化上限，不能只写“见隐私政策”。
providerModehost_brokered / user_configurable / vendor_only决定 Host 代发、用户可替换或强依赖厂商云。
userConfiguredOriginsallowed + maxOrigins只允许用户在 Host 中逐个授权精确 origin；仅用于 user_configurable。
authnone / host_session / host_credential / vendor_oauth秘密永远留在 Host 凭据库。
用户自配 Origin 不是通配权限

origins 是 Publisher 随 Source Manifest 提交的默认列表。用户新增地址只能在 Host 设置中逐个输入或选择并本地授权；App 和远端响应不能代填、扩宽或静默更换，也不会改写 Release Envelope。

权限扩大与状态

新增默认目标、用途、数据或 Component 等权限扩大必须重新审核并展示差异。用户拒绝后记为 permissions=denied；只有等待首次决定或重新同意时才使用 pending。

    07 · DATA CONTRACT

    共享命名合同，不共享裸文件或全库

    数据默认保存在按 App ID 隔离的 Private Store。网络权限不会自动获得另一个 App 的读取权， 也不能用“上传再下载”的方式绕过 Host。

    1. Import 请求导入方声明 Owner、Export、Schema、操作、目的和 Component。
    2. Export 允许Owner 声明命名 Store、Schema、操作与 Consumer 范围。
    3. 身份与同意Host 验证双方是同一签名 Publisher，并向用户展示数据方向。
    4. Broker 执行Host 发放受限 Handle、校验 Schema、记录调用与撤销。
    统一顶层：data

    data.privateStores[]、data.exports[] 与 data.imports[] 可以并存，不得另设共享顶层。

    Owner Source Manifest · data.exports[]示例
    {
  "data": {
    "privateStores": [
      { "id": "tasks", "schemaVersion": 1 }
    ],
    "exports": [{
      "id": "task-summary",
      "store": "tasks",
      "schema": "com.example.tasks.summary@1",
      "operations": ["query"],
      "consumers": [{
        "appId": "com.example.dashboard",
        "publisherId": "com.example.publisher"
      }]
    }],
    "imports": []
  }
}
    Importer Source Manifest · data.imports[]示例
    {
  "data": {
    "privateStores": [],
    "exports": [],
    "imports": [{
      "id": "tasks-summary",
      "componentId": "dashboard-ui",
      "ownerAppId": "com.example.tasks",
      "ownerPublisherId": "com.example.publisher",
      "exportId": "task-summary",
      "schema": "com.example.tasks.summary@1",
      "operations": ["query"],
      "required": false,
      "purpose": "在总览页显示待办数量"
    }]
  }
}
    建立 Share Grant 的精确匹配

    Owner 与 Importer 的签名 publisherId 必须相同；Importer 的 appId/publisherId 还要命中 Owner consumers[]，双方 ownerAppId、ownerPublisherId、exportId、schema 与 operations 也必须匹配。v1.1 不开放跨 Publisher 的直接 Store 共享；imports[].id 是 Importer 内的稳定合同 ID。

    合同允许不隐含
    query读取 Owner 明确导出的 View / 字段子集append、update、delete、原始表或全库
    append按 Schema 新增记录读取旧记录、修改或删除
    subscribe接收合同范围内的变更事件直接连接 Owner 数据库或继续转发给第三个 App
    双边声明不等于对称读写

    Importer Request 与 Owner Export Allow 只是双方同意一条有方向的合同。每种操作分别授权；Owner 可以只导出聚合 View。可选 Import 失败时，只降级依赖它的功能。

    禁止旁路

    不能打开另一 App 的 SQLite、共享目录或裸文件路径，也不能借云端、回环服务、CLI、Shell、浏览器或 Native Companion 绕过 Data Broker。

    08 · AI PROVIDERS

    把模型选择权和云依赖说清楚

    标准接口默认可替换；专有能力可以 vendor-only，但不能隐身。用户在购买前就应知道服务由谁运行、数据去哪里、费用由谁承担。

    API

    标准接口

    OpenAI-compatible 等公开协议必须允许配置 endpoint、model 与 Host credentialRef。发布者可以给默认值，但不能伪装服务商。

    V

    专有云

    明示运营方、域名、数据与留存、断网影响、停服影响、费用是否包含。审核方可要求说明为什么不可替换。

    费用分离

    用户自己的 API Key 产生的是用户与算力服务商之间的费用，不等于购买插件。插件订阅、功能解锁和插件方云服务仍走 Billing Broker。

    09 · BILLING BROKER

    每个 Component 只看被授权的稳定接口

    商品身份、价格、交易主体、支付渠道和最终权益都由 Host 决定。调用绑定 appId、componentId、publisherId 与 packageDigest。

    billing.purchase()

    仅授权可承载确认 UI 的 Component，并且必须由用户主动触发。

    billing.getEntitlement()

    前台或后台 Component 可按声明读取 Host 权威权益。

    billing.consume()

    后台 Component 可幂等扣减已授权用量；失败不收费、不执行动作。

    模式默认级别规则
    host_managed默认购买、恢复、退款映射、用量与权益全部通过 Host。
    none普通App 免费，不出现付费入口，也不能远端临时注入收费。
    external_authorized高权限例外绑定书面授权 ID、发行渠道、商品范围与撤销机制；缺少授权时强制阻止。
    component scope每次调用能力限制到具体 Component；购买、查询和扣量不能互相推导。
    外部支付不是警告级权限

    未获授权时返回 BILLING_EXTERNAL_NOT_AUTHORIZED。授权必须限制 App、Component、SKU、渠道和有效期；其他 Component 不得复用。

    11 · RULE EXPLORER

    按问题筛选规范

    搜索错误码、关键词或类别；所有条目都可用键盘展开。

    展开方式

    R-01能力按 Runtime Component 授予和审计

    每次调用绑定 appId、componentId、publisherId、packageDigest 与 componentKind；componentId 来自 Release Envelope 绑定的 Source Manifest，Component 之间不能借用能力。

    R-02复合运行时按 Component 独立降级

    protocol、activation、lifecycle 与 backgroundPolicy 都属于 Source Manifest 合同。可选失败聚合 health=degraded；必需失败聚合 health=unhealthy，并按原因更新 dependencies 或 permissions。

    N-01未声明目标默认阻止

    Source Manifest 没有命中的 origin、端口、协议和重定向不得发出。返回 NETWORK_UNDECLARED_DESTINATION，不可自动重试。

    N-02权限扩大必须重审与重新同意

    新增默认目标、用途、数据类别、留存或身份令牌，以及从可替换改为 vendor-only，全部作为权限扩大。用户拒绝后 permissions=denied；pending 只表示等待决定。

    S-01秘密只保存在 Host

    App 只持有不透明 credentialRef 或请求结果。Source Manifest、App 存储、日志、URL 和普通 IPC 中不得出现秘密。

    S-02远端响应永远不是新增代码

    禁止执行远端脚本、Wasm、二进制和动态工作流。模型动作建议仍要映射到 Host 已注册命令并重新经过能力授权。

    N-03标准 AI 接口默认可配置

    公开可替换协议提供 endpoint、model 与 Host credentialRef。userConfiguredOrigins 只允许用户在 Host 中逐个授权精确 origin，App 或远端不能代填，也不会改写 Release Envelope。

    D-01App-ID Private Store 默认隔离

    其他 App 默认不可见。共享对象是命名 Store、版本化 Schema 和允许操作，不是裸文件、SQLite、全库或目录 Handle。

    D-02双边声明、Publisher 校验与用户同意缺一不可

    v1.1 仅允许同一签名 publisherId 的 Owner 与 Importer；双边声明和 consumers 身份必须精确匹配，Host 取得用户同意后才发放 Data Handle。

    D-03双边合同不要求对称读写

    query、append、update、delete、subscribe 分别授权；读不隐含写。也不能借云端、CLI、回环服务或共享目录绕过 Host。

    D-04数据共享失败必须可归因、可降级

    DATA_IMPORT_UNDECLARED、DATA_EXPORT_NOT_ALLOWED、DATA_SCHEMA_MISMATCH、DATA_CONSENT_REQUIRED 与 DATA_BROKER_REVOKED 都绑定 Component 与 traceId；可选 Import 失败不阻止整个 App。

    B-01商品和权益由 Host 决定

    插件通过 purchase、getEntitlement、consume 工作；SKU、价格、渠道商品映射和最终权益来自 Host Catalog 与可信回执。

    B-02外部支付是高权限例外

    必须绑定书面授权、渠道、商品范围与撤销机制。授权无效时强制阻止，不能只给一个轻度警告。

    B-03用户算力费用与插件费用分开

    用户自己的模型 API Key 不自动构成绕过支付，也不自动授予插件权益。插件订阅、功能解锁和插件方云服务仍受 Billing Broker 管理。

    B-04撤销权益不删除用户数据

    退款、拒付或安全撤销停止付费能力，但应保留用户生成数据，除非用户主动删除。

    B-05计费能力也按 Component 分配

    purchase 只给可承载 Host 确认 UI 的 Component；后台 Component 可按声明查询权益或幂等扣量。外部支付授权不能跨 Component 复用。

    G-01现有 CLI 网络仍绕过 Host

    外部 CLI 自行联网，Host 无法提供完整域名白名单和出站审计。v1.1 只允许 direct 的官方 Adapter 调用，并明确标注“网络由外部应用负责”；Store 构建关闭 local_cli。

    G-02硬件支付不是插件计费系统

    Landing 已有实物订单与支付，但桌面端仍缺 Billing Broker、数字商品 Catalog、恢复购买、退款映射和权益服务。

    G-03Marketplace 条款是未来准入条件

    Core v1.1 是实现目标，direct 是受控发行阶段；公开入驻、销售和处罚仍属后续 Marketplace，不应在产品中显示为已上线。

    12 · CURRENT GAP

    从现状到 Core v1.1，还缺六块宿主能力

    这些是 Platform Core 的实现差距；direct 要等待对应门禁，Marketplace 仍是后续阶段。

    Runtime Identity

    Source Manifest、Release Envelope、稳定 Component 身份、protocol/backgroundPolicy、能力令牌与独立降级。

    Network Broker

    解析 Release Envelope 绑定的 Source Manifest、校验 origin 与重定向，并真实阻止未声明请求。

    Credential Broker

    复用系统凭据库，向 App 提供 credentialRef、OAuth 承载和脱敏日志。

    Private Store & Data Broker

    App-ID 隔离、双边合同、Publisher 身份、Schema Handle、用户同意和共享审计。

    Billing & Entitlement

    统一 SKU、购买、恢复、退款映射、用量账本、离线状态与撤销。

    Consent & Audit

    展示权限差异、重新同意、记录 Component 级网络/数据/计费事件，并隔离违规版本。

    开放门槛

    上述门禁落地前，不向普通第三方 App 开放任意联网、跨 App 数据、任意 CLI 或自行支付。公开 Marketplace、第三方销售与运营处罚也不是当前已交付功能。

    13 · ACCEPTANCE

    实现完成的判定标准

    “有配置页面”不算完成；必须用真实运行时测试证明边界有效。

    Runtime Components

    • 网络、数据和计费调用都有不可伪造的 componentId。
    • Component 不能借用彼此的能力令牌。
    • protocol、activation、lifecycle、backgroundPolicy 都被验证。
    • 可选失败聚合 health=degraded；必需失败聚合 health=unhealthy。

    网络

    • 未声明 App 无法访问外网。
    • 域名、端口和跨域重定向被真实校验。
    • 用户自配 origin 逐个授权，不能由 App 或远端代填。
    • 秘密不出现在 App、IPC 与日志。
    • 远端脚本、Wasm 和二进制不能执行。
    • 撤销权限后新请求立即停止。
    • Store 构建不含 local_cli；direct 会披露外部应用网络边界。
    • 第三方 App 不能借 CLI、Shell、curl 或浏览器绕过代理。

    跨 App 数据

    • App 默认只能访问自己的 Private Store。
    • Importer 与 Owner 双边声明必须精确匹配。
    • Host 确认 Owner 与 Importer 是同一签名 Publisher，并取得用户同意。
    • 只共享命名 Store、Schema 和分别授权的操作。
    • 网络、CLI 和共享目录不能绕过 Data Broker。

    AI 服务

    • 标准接口可配置 endpoint、model、credentialRef。
    • 用户能看见当前服务商、数据去向与费用方。
    • vendor-only 明示断网、停服和账号失效影响。
    • 用户自有 API Key 不会发给 Publisher。

    计费

    • 购买必须由用户触发，SKU 与价格来自 Host。
    • 购买、查权益与扣量分别归因到授权 Component。
    • consume 幂等，失败不收费也不执行动作。
    • 支持取消、pending、恢复、退款和撤销。
    • 未授权外部支付在运行时被强制阻止。

    审计与恢复

    • 事件可按 App、Component、版本和 traceId 查询。
    • 日志不含正文、秘密或支付卡数据。
    • 违规版本能被隔离，高权限能被撤销。
    • 失去权益不删除用户生成数据。
    • Core、direct、Marketplace 状态不会混为“已上线”。

    行业已有的共同做法

    ReAI 采用“显式声明、运行时限制、平台托管、例外审批”的交集，不照搬任何单一市场。

    Figma Plugin Manifest

    声明允许域名，运行时阻止未声明目标，并向用户展示网络范围。

    Atlassian Forge Remotes

    声明远端、数据用途、鉴权与客户可配置端点。

    Chrome Manifest V3

    远端可以提供数据，但扩展逻辑应自包含，不能通过远端代码改变功能。

    Shopify App Store

    App 收费默认走平台 Billing；站外支付需要平台明确允许。

    JetBrains Marketplace

    市场统一承载插件销售、订阅和许可管理。

    Atlassian Marketplace Billing

    平台计费、厂商计费与免费模式被明确分类和管理。

    Microsoft Store Policies 10.8

    非游戏 PC 产品可选择 Microsoft 或合规安全第三方支付，并承担披露与安全义务。

    Apple App Review Guidelines

    数字解锁、插件软件、逐项数据同意与原生能力暴露均受发行渠道约束。
